    sudo apt update
sudo apt install build-essential cmake cmake-qt-gui git ninja-build \
  libgl1-mesa-dev mesa-utils \
  xorg-dev libwayland-dev libxkbcommon-dev wayland-protocols \
  zlib1g-dev
# xorg-dev / wayland：從 submodule 編 GLFW 需要；zlib：Assimp 可能需要
  2. 確認 OpenGL 版本（需 core profile ≥ 4.1）： 
    glxinfo -B | grep -E "renderer|core profile version"
    NVIDIA 混合顯卡（Pop!_OS 可用 system76-power 切換）：__NV_PRIME_RENDER_OFFLOAD=1 __GLX_VENDOR_LIBRARY_NAME=nvidia ./app 用獨顯執行。

    git clone --recursive <url> hw1 && cd hw1
git switch <branch>   # 如需要
  4. Configure + Build（source 一樣是 builder）： 
    cmake -S builder -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
# GLFW 抱怨 Wayland 相關錯誤時可加：-DGLFW_BUILD_WAYLAND=OFF（走 X11 / XWayland）
  5. 執行：找出執行檔（find build -maxdepth 3 -type f -executable），在專案預期的工作目錄下執行，否則 assets / shaders 讀不到。template 若用 VS_DEBUGGER_WORKING_DIRECTORY 指定路徑，那只對 VS 有效 → Linux 需自己 cd 到對應目錄再跑。
  6. VS Code（選配）：裝 C/C++、CMake Tools；.vscode/settings.json 加： 
    { "cmake.sourceDirectory": "${workspaceFolder}/builder",
  "cmake.buildDirectory": "${workspaceFolder}/build" }
    並在 launch 設定 "cwd" 為資源所在目錄。
Linux 可能遇到的坑
  • 大小寫敏感：#include "Shader.h" vs 檔名 shader.h、Assets/ vs assets/ 在 Windows 沒事、Linux 會錯。
  • 路徑分隔：用 /，不要用 \\。
  • MSVC 專屬：#pragma comment(lib, ...)、fopen_s、<windows.h>、M_PI 需 _USE_MATH_DEFINES 等 → 用標準寫法或 #ifdef _WIN32 包起來。
  • CMakeLists 若寫死 .lib 或 Windows 路徑，需加 if(WIN32) 分支（改動前確認不影響 Windows build）。
  • GCC 比 MSVC 嚴格：缺 #include <cstring> / <algorithm> 等會報錯，補上即可（MSVC 也能編）。
  • Release 下的未初始化變數：Windows / Linux 行為可能不同，變數都要初始化。
  1. 安裝 CMake GUI、Xcode（App Store）、Git。
  2. Clone 與 Windows 相同。
  3. CMake GUI：source = builder、build = build → Configure 選 Xcode → Generate → Open Project → Run。
  4. OpenGL 在 macOS 已 deprecated、最高 4.1，需 GLFW_OPENGL_FORWARD_COMPAT。

GitLab 與 Git

Git 名詞白話版
名詞意思類比
Repository（repo）一個被 Git 管理的專案資料夾（含 .git/ 歷史紀錄）有版本紀錄的資料夾
Commit某一刻所有檔案的快照 + 說明訊息遊戲存檔點
Branch一條獨立的 commit 線；template 可能把每次作業放不同 branch（如 hw1）平行世界的存檔線
Remote遠端伺服器上的 repo（GitLab / GitHub）；origin、upstream 只是它的暱稱雲端備份
Clone第一次把整個 remote repo 複製到本機下載專案
Submodulerepo 裡面引用另一個 repo（GLFW、Assimp），只記錄「用哪個版本」捷徑，需另外下載內容
HTTP vs SSH URL兩種連線方式；HTTP 用帳密登入（講義要求），SSH 需設定金鑰—

一個實際情境：週一 clone 了 HW1 → 週二寫完相機控制，git add + git commit -m "camera" + git push → 週三改光照把程式改壞了 → git restore src/main.cpp 回到週二的版本；或 git log 找到想要的 commit，git diff <commit> 看改了什麼。

常見狀況
  • submodule 資料夾是空的（clone 時忘了 --recursive）：git submodule update --init --recursive

繳交流程

  • 上傳平台、檔名格式、要附的檔案：依每次作業公告（eeclass）。
  • 除了檔案本身，要算 MD5 checksum 填入 Google 表單：
    • 若因故無法在期限前上傳成功，以 checksum 比對 → 一致就不算遲交。
    • 多次登記取時間最晚的那筆 → 最後上傳的檔案要和最後登記的 MD5 一致。
    • 算完 MD5 後不能再動壓縮檔（重壓縮 MD5 就變了）。
MD5 是什麼？為什麼要填？

MD5 是一個檔案的「指紋」：把整個檔案內容算成 32 個 16 進位字元，例如 9e107d9d372bb6826bd81d3542a419d6。檔案改了任何一個 byte，指紋就完全不同。

你在期限前把指紋填進 Google 表單（表單有時間戳記）→ 就算上傳網站當機、晚了幾分鐘才傳成功，助教比對上傳檔的 MD5 與表單一致，就能證明「這個檔案在期限前就已完成」。

$ md5sum HW1_112000000.zip
9e107d9d372bb6826bd81d3542a419d6  HW1_112000000.zip     # 複製前面那串填表單
Linux
md5sum HW1_學號.zip
Windows（PowerShell / cmd）
Get-FileHash HW1_學號.zip -Algorithm MD5
certutil -hashfile HW1_學號.zip MD5

macOS：md5 file.zip。打包前刪掉 build/（很大且不需要）。Linux 打包：git archive -o HW1.zip HEAD（只含已 commit 的檔案，submodule 不含）或 zip -r HW1.zip . -x "build/*" ".git/*"。
