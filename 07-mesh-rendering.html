3D Model 的組成

  • 由 3D 美術用建模軟體製作
  • 定義一個場景，包含：
    • Scene：物件的配置 / 排列
    • Shape：表面的頂點與 index（三角形）
    • Material：表面的光照性質（顏色、貼圖…）
  • 一個 Object = 一個 Shape + 一個 Material；多個 object 可以共用同一個 material。

最直接的畫法：一次畫一個 object。每個 shape 載成一個 VAO、每個 material 載成一張 texture：

// C++
glBindVertexArray(cone_vao);
glBindTexture(GL_TEXTURE_2D, cone_tex);
glDrawElements(...);
glBindVertexArray(torus_vao);
glBindTexture(GL_TEXTURE_2D, torus_tex);
glDrawElements(...);
// cylinder、sphere 同理

Per-face Normal vs Per-vertex Normal

邊數 光源角度
可以讓 OpenGL 對同一個位置用不同 normal 嗎？

短答：不行。長答：GPU 為了最大平行度，不能讓 vertex shader 輸入共用 attribute；每次 vertex shader 呼叫都讀一整組 attribute（同一個 index 同時取位置和 normal）。所以必須複製位置——不管你做還是 GPU 做，佔的記憶體都一樣。

VBO#1 PositionVBO#2 Normal→ VS 呼叫
Position#1Normal#1VS#1 (P1, N1)
Position#1Normal#2VS#2 (P1, N2)
Position#1Normal#3VS#3 (P1, N3)
Position#1Normal#4VS#4 (P1, N4)

一個被 6 個面共用的頂點，若要 per-face normal → 1 個位置要配 6 個 normal → 拆成 6 個 GPU 頂點。

兩種都要清楚自己要哪一種；免費模型可能是 per-face、per-vertex 甚至混用，要小心處理。例：Ubisoft《Grow Home》刻意用 per-face 營造特殊美術風格。

3. 幾何 → VAO / VBO / IBO（補完版）

講義只給迴圈骨架，下面補上實際的 buffer 建立（3 個 VBO 分開存 = stacked 的一種）。

// C++
for (unsigned int i = 0; i < scene->mNumMeshes; ++i) {
    aiMesh* mesh = scene->mMeshes[i];
    std::vector<float> pos, nor, uv;
    std::vector<unsigned int> idx;
    for (unsigned int v = 0; v < mesh->mNumVertices; ++v) {
        pos.insert(pos.end(), { mesh->mVertices[v].x, mesh->mVertices[v].y, mesh->mVertices[v].z });
        if (mesh->HasNormals())
            nor.insert(nor.end(), { mesh->mNormals[v].x, mesh->mNormals[v].y, mesh->mNormals[v].z });
        if (mesh->HasTextureCoords(0))                  // mTextureCoords[0] = 第 0 組 UV
            uv.insert(uv.end(), { mesh->mTextureCoords[0][v].x, mesh->mTextureCoords[0][v].y });
        else
            uv.insert(uv.end(), { 0.0f, 0.0f });
    }
    for (unsigned int f = 0; f < mesh->mNumFaces; ++f)  // Triangulate 後每個 face 3 個 index
        for (int k = 0; k < 3; ++k)
            idx.push_back(mesh->mFaces[f].mIndices[k]);

    Shape shape;
    glGenVertexArrays(1, &shape.vao);
    glBindVertexArray(shape.vao);

    glGenBuffers(1, &shape.vbo_position);
    glBindBuffer(GL_ARRAY_BUFFER, shape.vbo_position);
    glBufferData(GL_ARRAY_BUFFER, pos.size() * sizeof(float), pos.data(), GL_STATIC_DRAW);
    glVertexAttribPointer(0, 3, GL_FLOAT, GL_FALSE, 0, 0);
    glEnableVertexAttribArray(0);
    // vbo_normal（location 1, size 3）、vbo_texcoord（location 2, size 2）同理

    glGenBuffers(1, &shape.ibo);
    glBindBuffer(GL_ELEMENT_ARRAY_BUFFER, shape.ibo);   // VAO 會記住 IBO
    glBufferData(GL_ELEMENT_ARRAY_BUFFER, idx.size() * sizeof(unsigned int), idx.data(), GL_STATIC_DRAW);

    shape.materialID = mesh->mMaterialIndex;
    shape.drawCount = mesh->mNumFaces * 3;
    shapes.push_back(shape);
}
aiReleaseImport(scene);   // 4. 資料都上傳到 GPU 後就釋放 scene

Appendix 的完整 C++ API 範例（含錯誤說明） 
// C++
#include <assimp/Importer.hpp>      // C++ importer interface
#include <assimp/scene.h>           // Output data structure
#include <assimp/postprocess.h>     // Post processing flags

void my_load_object(const char* const my_filepath) {
    Assimp::Importer importer;
    const aiScene* scene = importer.ReadFile(my_filepath,
        aiProcess_Triangulate | aiProcess_JoinIdenticalVertices | aiProcess_SortByPType);
    if (!scene) {
        std::cerr << "Fail to load Scene" << '\n' << importer.GetErrorString() << '\n';
        std::exit(1);
    }

    std::vector<MeshData> meshes;
    for (unsigned int i = 0; i < scene->mNumMeshes; i++) {
        aiMesh* aimesh = scene->mMeshes[i];
        MeshData mesh;
        bool hasNormals = aimesh->HasNormals();            // 講義沒定義，補上
        bool hasUV = aimesh->HasTextureCoords(0);
        for (unsigned int vi = 0; vi < aimesh->mNumVertices; ++vi) {
            const aiVector3D& p = aimesh->mVertices[vi];
            mesh.positions.insert(mesh.positions.end(), { p.x, p.y, p.z });
            if (hasNormals) {
                const aiVector3D& n = aimesh->mNormals[vi];
                mesh.normals.insert(mesh.normals.end(), { n.x, n.y, n.z });
            }
            if (hasUV) {
                const aiVector3D& t = aimesh->mTextureCoords[0][vi];
                mesh.texcoords.insert(mesh.texcoords.end(), { t.x, t.y });
            }
        }
        for (unsigned int fi = 0; fi < aimesh->mNumFaces; ++fi) {
            const aiFace& face = aimesh->mFaces[fi];
            for (int k = 0; k < 3; ++k) mesh.indices.push_back(face.mIndices[k]);
        }
        mesh.material_id = aimesh->mMaterialIndex;
        meshes.push_back(mesh);
    }

    std::vector<GLuint> textures;
    for (unsigned int i = 0; i < scene->mNumMaterials; i++) {
        aiMaterial* material = scene->mMaterials[i];
        aiString path;
        GLuint diffuseTexture = default_texture;            // 講義：只有找到貼圖才 push → index 會錯位
        if (material->GetTexture(aiTextureType_DIFFUSE, 0, &path) == AI_SUCCESS)
            diffuseTexture = loadTextureImage(path.data);   // 自己寫的讀圖 → GL texture
        textures.push_back(diffuseTexture);                 // 每個 material 都 push，textures[i] 才對得上
        // 其他類型（OPACITY、EMISSIVE…）同樣方式讀
    }
    // 講義寫 return meshes, textures; —— C++ 不能這樣回傳兩個值，改用參數或 struct
}

加速場景渲染：總覽

Algorithm view：少畫一點
  • Frustum culling：視錐外的物件不畫
  • Occlusion culling：被擋住的不畫（本課不講）
  • Distance culling：太遠的不畫
  • 回想：rasterizer 的 face culling 只丟背面三角形，但 CPU 送資料、vertex shader 的時間已經花掉了 → 最好在畫之前就判斷物件看不看得到
Implementation view：畫得有效率
  • 減少 draw call 數（instancing、multi-draw）
  • 減少 CPU ↔ GPU 的資料傳輸
  • GPU-driven rendering
  • Multi-thread rendering

Bounding Box 與平面測試

Bounding box：用簡單形狀粗略代表複雜物件，換取速度（容許一點誤差：box 在視錐內不代表物件本身看得到）。

AABB（Axis Aligned Bounding Box）：邊和 X、Y、Z 軸平行，只要存最小 / 最大角 amin、amax，或中心 + 半長：

c = (amax + amin) · 0.5
h = (amax − amin) · 0.5

平面方程：法向量 n = (a, b, c)、|n| = 1、平面上一點 (x₀, y₀, z₀)：

ax + by + cz + D = 0，D = −ax₀ − by₀ − cz₀
點到平面的有號距離 f(x,y,z) = ax + by + cz + D

Plane / AABB 相交測試

bool PlaneAABBIntersect(B, π)   // 回傳 OUTSIDE / INSIDE / INTERSECTING
c = (b.max + b.min) / 2;
h = (b.max - b.min) / 2;
e = h.x*|n.x| + h.y*|n.y| + h.z*|n.z|;  // box 往法向量方向最長的投影半徑
s = dot(c, n) + D;                      // 中心到平面的有號距離
if (s - e > 0) return OUTSIDE;          // 整個 box 在正半空間
if (s + e < 0) return INSIDE;           // 整個 box 在負半空間
return INTERSECTING;

這裡把法向量指向的正半空間當作「外面」（講義圖示）。|s| > e 就一定不相交。實作參考 3D Collisions Ch.2。

Frustum Culling

從矩陣求視錐的 6 個平面

NDC 點 u、clip space 點 t、世界座標點 s：uxyz = txyz / tw，t = M · s，M = P · V。設 mi 為 M 的第 i 列（row）。

以 x 為例，點在左平面內側：

−1 ≤ ux ⇔ −1 ≤ tx/tw ⇔ tx + tw ≥ 0
⇔ (m0·s) + (m3·s) ≥ 0 ⇔ (m0 + m3)·s ≥ 0

（假設 tw > 0，即點在相機前方）

平面內側條件平面（法向量朝外，講義寫法）
left(m₃ + m₀)·s ≥ 0−(m₃ + m₀)·(x,y,z,1) = 0
right(m₃ − m₀)·s ≥ 0−(m₃ − m₀)·(x,y,z,1) = 0
bottom(m₃ + m₁)·s ≥ 0−(m₃ + m₁)·(x,y,z,1) = 0
top(m₃ − m₁)·s ≥ 0−(m₃ − m₁)·(x,y,z,1) = 0
near(m₃ + m₂)·s ≥ 0−(m₃ + m₂)·(x,y,z,1) = 0
far(m₃ − m₂)·s ≥ 0−(m₃ − m₂)·(x,y,z,1) = 0

每個平面的係數 (a, b, c, D) 要除以 |(a, b, c)| 正規化，Plane/AABB 測試的 s 才是真正距離。GLM 是 column-major：第 i 列 = glm::vec4(M[0][i], M[1][i], M[2][i], M[3][i])。

bool FrustumAABBIntersect(π0..π5, B)
intersecting = false;
for (k = 0; k <= 5; k++) {
    result = PlaneAABBIntersect(B, πk);
    if (result == OUTSIDE) return OUTSIDE;     // 在任一平面外 → 整個在視錐外
    else if (result == INTERSECTING) intersecting = true;
}
if (intersecting) return INTERSECTING;
else return INSIDE;
// C++：render loop 加上 culling
for (int i = 0; i < numShapes; ++i) {
    if (FrustumAABBIntersect(shapes[i].AABB, camera.Frustum) == OUTSIDE)
        continue;                               // 看不到就跳過 draw call
    glBindVertexArray(shapes[i].vao);
    glBindTexture(GL_TEXTURE_2D, materials[shapes[i].materialID].diffuse_tex);
    glDrawElements(GL_TRIANGLES, shapes[i].drawCount, GL_UNSIGNED_INT, 0);
}

互動：Frustum culling（俯視圖）

相機方向 FOV far

INSIDE INTERSECTING → 要畫；OUTSIDE → 跳過。2D 只有 left / right / near / far 四個平面，3D 再加 top / bottom。

階層式 Frustum Culling

  • 逐一測試所有物件是 O(n)；用階層結構可以到 O(log n)
  • 任何有空間一致性的結構都適用：
    • 父節點完全在內 → 所有子節點都在內（不用再測）
    • 父節點完全在外 → 所有子節點都在外（整棵子樹跳過）
    • 相交 → 往下測子節點
結構建構方式特點
kd-treeTop-down：沿軸交替切空間切的是空間；問題：跨越格子邊界的物件要放哪？
OctreeTop-down：每格切成 8 個子格
BSP-treeTop-down：用任意平面切
BVH（Bounding Volume Hierarchy）Bottom-up：把相近物件的 bounding box 合併成更大的 box切的是物件，每個物件只屬於一個節點

Instancing：把整個矩陣當 vertex attribute

講義 05 用 instancing 傳 vec3 offset（只能平移，見 Instancing）。要旋轉、縮放 → 傳整個 mat4。但 glVertexAttribPointer 的 size 只能是 1~4，一個矩陣有 16 個數字 → 每個 column 一個 attribute。

location內容sizestrideoffset（byte）divisor
1column 046401
2column 1464161
3column 2464321
4column 3464481

每個 instance 的矩陣 = 64 bytes（16 float，column-major，正好是 glm::mat4 的記憶體排列）；一格 = 4 float = 16 bytes。

// C++
glBindBuffer(GL_ARRAY_BUFFER, matrix_buffer);   // 每個 instance 一個 glm::mat4
for (int c = 0; c < 4; c++) {
    glVertexAttribPointer(1 + c, 4, GL_FLOAT, GL_FALSE, 64, (void*)(c * 16));
    glEnableVertexAttribArray(1 + c);
    glVertexAttribDivisor(1 + c, 1);             // 每個 instance 換一筆（講義沒寫，但必要）
}

Multi-draw：不同 mesh 一次畫

Instancing 只能重複畫同一個 mesh。不同 mesh（Heterogeneous）要一次畫：

  1. 初始化：把所有要畫的 mesh 放進同一個 VBO（用 index 的話也放進同一個 IBO）
  2. 繪製：用 multi-draw API：glMultiDrawArrays、glMultiDrawElements、glMultiDrawElementsBaseVertex

選一個呼叫方式，看它讀了 index buffer 的哪一段、加上 baseVertex 後取到 VBO 的哪些頂點。紅 = mesh 1（ABCD）、綠 = mesh 2（EFGHK）。一格 VBO = 3 float（12 bytes），一格 index = 4 bytes（GL_UNSIGNED_INT）。

//                                         indirect offset ↑  drawcount ↑ stride（0 = 緊密）

和 mesh 資料（頂點、法向量、index…）比起來，draw 參數很小，單看傳輸量好處不大。真正的好處：

  • 把 indirect buffer 改用 SSBO（shader storage buffer：shader 可讀也可寫）存
  • → GPU 可以自己寫 draw command 的參數（例如 compute shader 做完 culling 後填 instanceCount）
  • → CPU 完全不用知道要畫幾個 → GPU-driven rendering
// C++：同一塊 buffer 同時當 SSBO 和 indirect buffer
glBindBuffer(GL_SHADER_STORAGE_BUFFER, cmdBufferHandle);
glBufferStorage(GL_SHADER_STORAGE_BUFFER, sizeof(drawCommands), drawCommands, GL_MAP_READ_BIT);
glBindBufferBase(GL_SHADER_STORAGE_BUFFER, 3, cmdBufferHandle);   // binding point 3
glBindBuffer(GL_DRAW_INDIRECT_BUFFER, cmdBufferHandle);

glMultiDrawElementsIndirect 等於多次 glDrawElementsInstancedBaseVertexBaseInstance，參數從 buffer 讀（綁了 GL_DRAW_INDIRECT_BUFFER 時 indirect 是 byte offset）。4.3+；SSBO / compute shader 也是 4.3+，macOS（4.1）不支援。

GPU-driven Rendering：Instance Culling

Compute Shader：通用的 shader，用 OpenGL API + GLSL 寫 GPU 平行程式；限制比 vertex / fragment shader 少；不屬於 graphics pipeline；OpenGL 4.3+；細節之後的講義會講。

情境：草地有 131,072 根草，每根只差在位置（一個 vec3 offset）。看不到的草想跳過——但 vertex shader 無法「丟掉」某個 instance，只能在 draw 之前決定畫哪些。

// C++：初始化三個 SSBO
const int NUM_GRASS = 131072;
// 1. 全部 instance 資料（vec4 position，std430 對齊用 vec4）
glBindBuffer(GL_SHADER_STORAGE_BUFFER, wholeDataBufferHandle);
glBufferStorage(GL_SHADER_STORAGE_BUFFER, NUM_GRASS * 4 * sizeof(float), grassOffsets, GL_MAP_READ_BIT);
glBindBufferBase(GL_SHADER_STORAGE_BUFFER, 1, wholeDataBufferHandle);
// 2. 這一幀可見的 instance
glBindBuffer(GL_SHADER_STORAGE_BUFFER, visibleBufferHandle);
glBufferStorage(GL_SHADER_STORAGE_BUFFER, NUM_GRASS * 4 * sizeof(float), NULL, 0);
glBindBufferBase(GL_SHADER_STORAGE_BUFFER, 2, visibleBufferHandle);
// 3. draw command（instanceCount 先設 0）
DrawElementsIndirectCommand drawCommands[1] = { { numIndex, 0, 0, 0, 0 } };
glBindBuffer(GL_SHADER_STORAGE_BUFFER, cmdBufferHandle);
glBufferStorage(GL_SHADER_STORAGE_BUFFER, sizeof(drawCommands), drawCommands, GL_MAP_READ_BIT);
glBindBufferBase(GL_SHADER_STORAGE_BUFFER, 3, cmdBufferHandle);

// C++：每一幀
glUseProgram(resetProgram);                       // compute #1：instanceCount = 0
glDispatchCompute(1, 1, 1);
glMemoryBarrier(GL_SHADER_STORAGE_BARRIER_BIT);   // 等前一步寫完才讀
glUseProgram(collectProgram);                     // compute #2：收集可見 instance
glDispatchCompute(NUM_GRASS / 1024, 1, 1);

glUseProgram(renderProgram);

#version 430 core
layout (local_size_x = 1, local_size_y = 1, local_size_z = 1) in;
struct DrawCommand {
    uint count; uint instanceCount; uint firstIndex;
    uint baseVertex; uint baseInstance;
};
layout (std430, binding = 3) buffer DrawCommandsBlock {
    DrawCommand commands[];
};
void main() {
    const uint idx = gl_LocalInvocationID.x;
    commands[idx].instanceCount = 0;
}
// GLSL：Compute Shader #2 Collect
#version 430 core
layout (local_size_x = 1024, local_size_y = 1, local_size_z = 1) in;
struct DrawCommand { uint count; uint instanceCount; uint firstIndex; uint baseVertex; uint baseInstance; };
struct InstanceProperties { vec4 position; };
layout (std430, binding = 3) buffer DrawCommandsBlock { DrawCommand commands[]; };
layout (std430, binding = 1) buffer InstanceData { InstanceProperties instanceProps[]; };
layout (std430, binding = 2) buffer CurrValidInstanceData { InstanceProperties currValidInstanceProps[]; };
void main() {
    const uint idx = gl_GlobalInvocationID.x;
    if (/* visible */) {
        // atomicAdd 回傳「加之前」的值 → 拿到不重複的位置
        currValidInstanceProps[atomicAdd(commands[0].instanceCount, 1)] = instanceProps[idx];
    }
}
// GLSL：Vertex Shader（用 gl_InstanceID 讀可見清單）
#version 430 core
layout (location = 0) in vec3 vertex;
uniform mat4 viewProjMatrix;
struct InstanceProperties { vec4 position; };
layout (std430, binding = 2) buffer CurrValidInstanceData { InstanceProperties currValidInstanceProps[]; };
void main() {
    gl_Position = viewProjMatrix * (vec4(vertex, 1.0) + currValidInstanceProps[gl_InstanceID].position);
}

講義 vertex shader 的 uniform 名 viewProjMatrix 和使用處 viewProjMat 不一致，要統一。

Multi-thread Rendering

單執行緒：CPU 準備一幀時 GPU 閒著、GPU 畫的時候 CPU 閒著。多執行緒：game thread、render thread、GPU 像流水線一樣同時處理不同幀。OpenGL 的 context 綁定單一執行緒，多執行緒提交是 Vulkan 等新 API 的設計重點（GDC 2015 Khronos：Vulkan Explicit GPU Control）。

結論：提升 renderer 效率

  • Distance culling
Implementation view
  • 減少 draw call 數
  • 減少 CPU ↔ GPU 資料傳輸
  • GPU-driven rendering
  • Multi-thread rendering
