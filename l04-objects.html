講義 04 · OpenGL Objects

OpenGL Objects：資料怎麼送進 GPU

OpenGL 把資料傳給 GPU 的三種管道：Buffer（大量的頂點 / index / 結構資料）、Uniform（一次 draw call 內不變的參數）、Texture（可以被過濾取樣的影像）。

本章重點
  • Buffer 是一段線性記憶體；用途由它綁到哪個 binding point決定（GL_ARRAY_BUFFER、GL_ELEMENT_ARRAY_BUFFER、GL_UNIFORM_BUFFER…）。glGenBuffers 只產生名字，第一次 bind 才真正建立物件。
  • glBufferData 配置（並可初始化）、glBufferSubData 更新部分、glMapBuffer 直接寫記憶體；它們都作用在目前綁在那個 binding point 上的 buffer。
  • Uniform 在一次 draw 中對所有 shader 呼叫都相同。Default block uniform 存在 program 裡：glGetUniformLocation → glUseProgram → glUniform*。
  • Uniform block（UBO）把 uniform 存在 buffer 裡：block ↔ uniform binding point ↔ buffer；記憶體要照 std140 對齊。
  • Texture 透過 texture image unit 接到 shader：glActiveTexture(GL_TEXTUREn) + glBindTexture，sampler uniform 存的是 unit 編號 n，不是 texture ID。
  • Texture 和 buffer 最大的差別：texture 可以被過濾（nearest、bilinear、mipmap、anisotropic）和包裹（wrap）。

Buffer

Buffer 是什麼
  • 一段線性配置的記憶體，可能在主記憶體或顯示卡記憶體
  • 依用途分類：vertex buffer、index buffer、uniform buffer、shader storage buffer…
  • 所有種類的建立和上傳方式都一樣，差別只在綁到哪個 binding point
種類內容與用途
Vertex / Index每個頂點的輸入（位置 XYZ、UV…），像陣列；由 Vertex Specification stage 讀取，組成 VS 的輸入
Uniform一次 draw 內不變、GPU 唯讀最佳化；每個 shader 呼叫看到同樣內容。比較像 struct：相機設定、光源位置
Shader Storage（SSBO）像 uniform buffer，但 shader 可讀寫的自訂型別陣列；4.3+，講義 07 用到

建立 buffer object 的四步驟（互動）

重點：glGenBuffers 只拿到一個名字（unsigned int），buffer object 還不存在；第一次 glBindBuffer 才建立物件；glBufferData 才配置記憶體。

Binding point（binding target）

OpenGL 用 buffer 的方式由它綁在哪裡決定。要把 buffer 接到 pipeline、或對它做任何操作，都必須先綁到一個 binding point。（講義：Please pay attention to this!）

Buffer 資料：配置、更新、映射

函式做什麼特性
glBufferData(target, size, data, usage)建立新的資料儲存空間，size bytes；data 不是 NULL 就拿它初始化舊的空間會被釋放；可以只配置（data = NULL）
glBufferSubData(target, offset, size, data)從 byte offset 開始，把 size bytes 換成 data 的內容更新部分或全部，比 glBufferData 快
glMapBuffer(target, access) / glUnmapBuffer把整個 buffer 映射到 CPU 位址空間，直接讀寫；unmap 時改動才生效access：GL_READ_ONLY / GL_WRITE_ONLY / GL_READ_WRITE
// C++：三個函式都作用在「目前綁在該 binding point 上的 buffer」
// bind Buffer Object "buffer" to the "GL_ARRAY_BUFFER" Binding Point
glBindBuffer(GL_ARRAY_BUFFER, buffer);
// manipulate the buffer bound to "GL_ARRAY_BUFFER", which is "buffer"
glBufferData(GL_ARRAY_BUFFER, sizeof(data), data, GL_STATIC_DRAW);

// 先配置 1 MB 空的，之後再填
glBufferData(GL_ARRAY_BUFFER, 1024 * 1024, NULL, GL_STATIC_DRAW);
glBufferSubData(GL_ARRAY_BUFFER, 0, sizeof(data), data);

// 或用 map：拿到指標直接寫
void* ptr = glMapBuffer(GL_ARRAY_BUFFER, GL_WRITE_ONLY);
memcpy(ptr, data, sizeof(data));
glUnmapBuffer(GL_ARRAY_BUFFER);   // 告訴 OpenGL 寫完了
glMapBuffer 一定比較快嗎？

可能比 glBufferSubData 快：例如載入模型檔時，不用先自己配置一塊記憶體再呼叫 glBufferSubData，可以直接把檔案內容讀進 glMapBuffer 回傳的記憶體（少一次複製）。

不一定！要看顯示卡 driver 怎麼實作這個函式（講義：Not always True）。

Uniform

什麼是 uniform
  • 宣告在 shader 裡、讓應用程式直接把資料傳給 shader的變數
  • 叫 uniform 是因為在一次 draw command 中保持不變：不能被修改、每個 shader 呼叫讀到相同內容
  • 常放：相機 projection 矩陣、光源設定、texture sampler
  • 存在針對「同步唯讀存取」最佳化的特殊硬體記憶體
兩種機制Default block uniformBuffer-backed uniform block
出現OpenGL 2.0（舊）OpenGL 3.1
資料存在shader program objectbuffer object（UBO）
更新一個一個 glUniform*一次 glBufferSubData 更新全部
多個 program 共用不行，每個 program 各自設定綁到同一個 binding point 就共用

Default block uniform

同名宣告 = 同一個變數

Uniform 宣告在所有 programmable stage 間共用；同樣的宣告指向同一份資料。只需要在用到它的 stage 宣告。點 uniform 名稱看哪些是同一個：

存在 program 裡的狀態
  • Default block uniform 是 shader program object 的狀態
  • 更新 uniform 值之前要先 bind（glUseProgram）program
  • 值會一直存在 program 裡 → 沒變的值不用每幀重設
  • 每個 uniform 在 program 中用一個 uniform location（整數）識別
使用步驟
  1. 在 shader 程式碼宣告 uniform
  2. 編譯、attach、link shader program
  3. 用 glGetUniformLocation() 取得每個 uniform 的 location
  4. 用 glUseProgram() bind program
  5. 用 glUniform*() 更新某個 location 的值
  6. 發出 draw command

glUniform* 的命名規則

寫法意思例子
glUniform{1|2|3|4}{f|i|ui}(loc, v0, v1, …)數字 = 幾個分量；f / i / ui = float / int / unsigned int；直接傳值glUniform3f(loc, 1, 0.5, 0) → vec3
glUniform{1|2|3|4}{f|i|ui}v(loc, count, ptr)結尾 v = 傳指標；count = 陣列元素數（非陣列填 1）glUniform3fv(loc, 1, &color[0])
glUniformMatrix{2|3|4|2x3|…}fv(loc, count, transpose, ptr)矩陣；transpose = 是否轉置（GLM 是 column-major → GL_FALSE）glUniformMatrix4fv(loc, 1, GL_FALSE, glm::value_ptr(M))

範例：Spinning Cube 與 Many Spinning Cubes

一個立方體的頂點資料只上傳一次到 buffer；每一幀只改 uniform（矩陣）再 draw，立方體就會轉。Many Spinning Cubes 則是同一份資料、在一個迴圈裡換 24 次矩陣、draw 24 次。

這個範例要看懂的三件事
  • position 是 vertex attribute：資料在 buffer object 裡，VAO 記住「location 0 從這個 buffer 讀 3 個 float」，VS 的 in vec4 position 每次拿到一個頂點。→ ①
  • 兩個 uniform 更新頻率不同：proj_matrix 只跟視窗寬高比有關，視窗大小改變時才重算；mv_matrix 跟時間有關，每幀都要重算。→ ②
  • glUniformMatrix4fv 只寫值、不建立：uniform 在 GLSL 宣告、link 時誕生；C++ 只能查 location、寫值。→ 說明
  • for 迴圈的 24 = 畫 24 個立方體：每圈換一個 mv_matrix、呼叫一次 glDrawArrays（36 個頂點）。和 36 無關。→ ③

     0.25f, -0.25f, -0.25f,      // 第 2 個三角形

{

    vs_out.color = position * 2.0 + vec4(0.5, 0.5, 0.5, 0.0);

疑問答案
position 是 buffer object 嗎？不是 buffer 本身，是 vertex attribute（VS 的輸入變數）。它的值來自 buffer：glDrawArrays(GL_TRIANGLES, 0, 36) 讓 VS 跑 36 次，第 k 次拿到 buffer 裡第 k 組 (x, y, z)。
VS 沒寫 layout(location = 0)，怎麼知道是 0？沒寫時由 linker 自己分配 location。只有一個 attribute 時通常是 0，但不保證。穩妥的寫法：layout(location = 0) in vec4 position;，或 C++ 用 glGetAttribLocation(program, "position") 查。
buffer 給 3 個 float，VS 卻宣告 vec4？可以。缺的分量自動補上預設值 (0, 0, 0, 1) 裡對應的那個 → w = 1。所以 position = (x, y, z, 1)，剛好是矩陣平移需要的齊次座標。
顏色怎麼來？position * 2.0 + 0.5：座標 −0.25 → 0、+0.25 → 1，所以每個角的 (R, G, B) = 它的 (x, y, z) 是正或負。例如角 (+0.25, −0.25, +0.25) → 洋紅色 (1, 0, 1)。

② 兩個 uniform 什麼時候更新

glUniformMatrix4fv 是在「建立」uniform 還是「更新」它的值？

只是寫入值（更新）。OpenGL 沒有「建立 uniform」的函式：uniform 是在 GLSL 裡宣告、在 link 時由 program 配置好空間的。C++ 端只能查它的編號、寫它的值。

#步驟誰做發生什麼事
1宣告 uniform mat4 mv_matrix;GLSL 原始碼只是說「這個 shader 需要一個叫 mv_matrix 的 mat4」
2glLinkProgram(program)C++ → driveruniform 在這裡誕生：program 裡配置 16 個 float 的空間、分配一個 location 編號，初始值全為 0
3glGetUniformLocation(program, "mv_matrix")C++，link 後一次查編號（例如 0）。不會建立任何東西；名字打錯或 shader 沒用到 → 回傳 −1
4glUseProgram(program)C++選定「目前的 program」；下一步寫入的就是這個 program 的 uniform
5glUniformMatrix4fv(mv_location, 1, GL_FALSE, ptr)C++，需要改值時把 16 個 float 複製進 program 裡那格空間（覆蓋舊值）
6glDrawArrays(…)C++ → GPU這次 draw 的每個頂點都讀到同一個 mv_matrix
// glUniformMatrix4fv 的 4 個參數
glUniformMatrix4fv(mv_location,    // 寫到哪個 uniform（步驟 3 查到的編號）
                   1,              // 寫幾個 mat4（不是陣列就填 1）
                   GL_FALSE,       // 要不要轉置；GLM 已是 column-major → 不用
                   glm::value_ptr(mv_matrix));   // 16 個 float 的起點
  • 值會一直留著：寫入後存在 program 裡，直到下次再寫。所以 proj_matrix 不變時可以不用每幀重寫。
  • 寫給「目前的 program」：沒先 glUseProgram（或用了別的 program）就會寫錯對象，或產生 GL_INVALID_OPERATION。
  • location = −1 時：呼叫會被默默忽略，不報錯 → 畫面不對時先印出 location 檢查。
  • 每個 program 各有一份：兩個 program 都宣告 mv_matrix，要各自寫（共用要用 UBO）。
uniform跟什麼有關什麼時候重算原因
proj_matrix視角、視窗寬高比、near / far視窗大小改變時（OnReshape）視窗沒變，它就不會變，不用每幀算
mv_matrix時間（旋轉角度、位置）每一幀每幀時間都不同
// C++：視窗大小改變時呼叫（講義的 OnReshape）
void OnReshape(int w, int h)
{
    glViewport(0, 0, w, h);
    float aspect = (float)w / (float)h;   // 講義寫成 / (float)f，是筆誤
    proj_matrix = glm::perspective(glm::radians(50.0f),
                                   aspect, 0.1f, 1000.0f);
}

// 用 GLFW 的話：註冊成 framebuffer size callback
glfwSetFramebufferSizeCallback(window,
    [](GLFWwindow*, int w, int h) { OnReshape(w, h); });
// C++：render（每幀，一個立方體）
float f = (float)currentTime * 0.3f;
glm::mat4 mv_matrix = my_compute_mv_matrix(f);   // 每幀重算

glUseProgram(program);
glUniformMatrix4fv(mv_location, 1, GL_FALSE,
                   glm::value_ptr(mv_matrix));
glUniformMatrix4fv(proj_location, 1, GL_FALSE,    // 值是 OnReshape 算好的
                   glm::value_ptr(proj_matrix));
glDrawArrays(GL_TRIANGLES, 0, 36);

講義的寫法是「計算只在 reshape 做、上傳仍每幀做」。也可以連上傳都移到 OnReshape（先 glUseProgram）：uniform 的值存在 program 裡，不改就一直保留。

③ Many Spinning Cubes：for 迴圈的 24

// C++：render（Many Spinning Cubes）
glUseProgram(program);
glUniformMatrix4fv(proj_location, 1, GL_FALSE,
                   glm::value_ptr(proj_matrix));

for (int i = 0; i < 24; ++i)              // 24 = 要畫幾個立方體
{
    float f = (float)i + (float)currentTime * 0.3f;   // 每個差 1
    glm::mat4 mv_matrix = my_compute_mv_matrix(f);
    glUniformMatrix4fv(mv_location, 1, GL_FALSE,
                       glm::value_ptr(mv_matrix));
    glDrawArrays(GL_TRIANGLES, 0, 36);    // 畫 1 個立方體
}
// 講義沒給 my_compute_mv_matrix 的內容，本頁示範用這個寫法：
// f 決定立方體的位置與旋轉角度
glm::mat4 my_compute_mv_matrix(float f)
{
    glm::mat4 m(1.0f);
    m = glm::translate(m, glm::vec3(0.0f, 0.0f, -6.0f));  // 推到相機前方
    float x = std::sin(2.1f * f) * 2.0f;
    float y = std::cos(1.7f * f) * 2.0f;
    float z = std::sin(1.3f * f) * std::cos(1.5f * f) * 2.0f;
    m = glm::translate(m, glm::vec3(x, y, z));          // 依 f 決定位置
    m = glm::rotate(m, f * 3.0f, glm::vec3(0, 1, 0));    // 繞 y 轉
    m = glm::rotate(m, f * 2.0f, glm::vec3(1, 0, 0));    // 繞 x 轉
    return m;
}
數字意思
24立方體的個數，範例自己選的，改成 10 就畫 10 個。每一圈 = 一次 draw call = 一個立方體。
36一個立方體的頂點數（6 面 × 2 三角形 × 3 頂點），每次 draw 都一樣，因為用的是同一份 buffer。
f = i + time × 0.3每個立方體的參數差 1 → 位置、角度都不同；時間一走，全部沿著同一條曲線前進（像一列火車）。
一幀總共24 次 glDrawArrays，24 × 36 = 864 次 VS 執行；proj_matrix 只設 1 次、mv_matrix 設 24 次。

uniform「在一次 draw 內不變」，但兩次 draw 之間可以改，所以同一份頂點資料能畫在 24 個地方。24 次 draw call 的負擔與 instancing 改法見 講義 07。

Uniform location 的排列

一般來說，uniform 陣列佔用連續的 location。下面三種寫法效果相同：

為了避免 location 算錯：每個 uniform 都用 glGetUniformLocation() 查，或改用 buffer-backed uniform block。

Buffer-backed Uniform Block（UBO）

把一組 uniform 打包成一個 uniform block，資料改放在一個 buffer object 裡。好處：一次更新全部、多個 program 共用同一份。

為什麼需要：default uniform 的麻煩

假設有兩個 program（畫場景的 sceneProg、畫天空的 skyProg），都要用到相機的 view、proj。用一般 uniform 時，每個 program 各有一份，要各自查 location、各自寫：

// 一般 uniform：每幀要對每個 program 各寫一次
glUseProgram(sceneProg);
glUniformMatrix4fv(sceneViewLoc, 1, GL_FALSE, glm::value_ptr(V));
glUniformMatrix4fv(sceneProjLoc, 1, GL_FALSE, glm::value_ptr(P));
glUseProgram(skyProg);
glUniformMatrix4fv(skyViewLoc, 1, GL_FALSE, glm::value_ptr(V));
glUniformMatrix4fv(skyProjLoc, 1, GL_FALSE, glm::value_ptr(P));
// program 越多、uniform 越多，這段就越長，也容易漏寫一個
一般 uniform（default block）Uniform block（UBO）
資料存在每個 program 裡各一份一個 buffer object，大家讀同一份

三層關係：block ↔ binding point ↔ buffer

Block 和 buffer 不是直接連起來，中間隔著一排編號的 uniform binding point（0, 1, 2, …）。可以把 binding point 想成插座：

兩邊各自指定編號，編號一樣才接得上。好處：換資料只要把另一個 buffer 插進同一個插座，program 完全不用改。

完整例子：兩個 program 共用相機資料

① GLSL：兩個 shader 都宣告一模一樣的 block（名稱、成員、順序都要相同）。

// GLSL：scene.vs.glsl 和 sky.vs.glsl 都寫這段
layout(std140) uniform Camera      // block 名稱：C++ 用它查 index
{
    mat4  view;                     // offset   0，64 bytes
    mat4  proj;                     // offset  64，64 bytes
    vec3  eyePos;                   // offset 128，12 bytes
    float time;                     // offset 140， 4 bytes（剛好塞進 vec3 後面）
};                                  // 總共 144 bytes

void main()
{
    // 沒寫 instance 名稱時，成員直接當一般變數用
    // （model、aPos 照常用一般 uniform / attribute 宣告，這裡省略）
    gl_Position = proj * view * model * vec4(aPos, 1.0);
}

② C++：用一個 struct 對應 block 的排列

struct CameraData                   // 欄位順序、大小都和 GLSL 的 block 一致
{
    glm::mat4 view;                 // 0
    glm::mat4 proj;                 // 64
    glm::vec3 eyePos;               // 128
    float     time;                 // 140
};
static_assert(sizeof(CameraData) == 144, "要和 std140 的大小一樣");

這個例子剛好不需要 padding（vec3 後面接 float）。如果把 time 拿掉、或 vec3 後面接 vec3，就要自己補空位，規則見 std140。

③ C++：初始化（只做一次）

GLuint ubo;
glGenBuffers(1, &ubo);
glBindBuffer(GL_UNIFORM_BUFFER, ubo);
glBufferData(GL_UNIFORM_BUFFER, sizeof(CameraData),
             nullptr, GL_DYNAMIC_DRAW);       // 只配置 144 bytes，先不放資料

// buffer → 插進 0 號 binding point
glBindBufferBase(GL_UNIFORM_BUFFER, 0, ubo);

// 每個 program 的 Camera block → 去 0 號拿
GLuint sceneIdx = glGetUniformBlockIndex(sceneProg, "Camera");
glUniformBlockBinding(sceneProg, sceneIdx, 0);
GLuint skyIdx = glGetUniformBlockIndex(skyProg, "Camera");
glUniformBlockBinding(skyProg, skyIdx, 0);

④ C++：每一幀更新

glUseProgram(sceneProg);   // 畫場景：Camera 已經是新的
// … draw …

// … draw …
  • 只想改其中一個欄位，可以只寫那段：glBufferSubData(GL_UNIFORM_BUFFER, 140, 4, &time);（offset 140、4 bytes）。
  • glBindBufferBase 也會順便把 buffer 綁到一般的 GL_UNIFORM_BUFFER，所以上面的 glBindBuffer 嚴格說可以省略；寫出來比較清楚。

講義的例子：X、Y、Z 三個 block

講義的設定：Uniform Block X 用 Buffer C、Y 用 A、Z 用 B。重點是 binding point 不必連續（2 沒用到），也不必和 block 宣告的順序一樣。點右邊的 block 看路徑。

// GLSL
uniform X { float a; mat4 b; };
uniform Y { int c; ivec4 d; };
uniform Z { mat4 e[10]; };
// C++：block → binding point
GLuint X_index = glGetUniformBlockIndex(program, "X");
GLuint Y_index = glGetUniformBlockIndex(program, "Y");
GLuint Z_index = glGetUniformBlockIndex(program, "Z");
glUniformBlockBinding(program, X_index, 1);
glUniformBlockBinding(program, Y_index, 3);
glUniformBlockBinding(program, Z_index, 0);

// C++：buffer → binding point
glBindBufferBase(GL_UNIFORM_BUFFER, 0, buffer_b);   // Z 的資料
glBindBufferBase(GL_UNIFORM_BUFFER, 1, buffer_c);   // X 的資料
glBindBufferBase(GL_UNIFORM_BUFFER, 3, buffer_a);   // Y 的資料

Texture

幾何建模的極限

現代顯卡每秒能畫超過 100 億個三角形，但只靠幾何，很多擬真的場景還是不夠細。

例：做一顆橘子

  1. 橘色的球 → 太簡單
  2. 換更複雜的形狀 → 抓不到表面特徵
  3. 加上小凹洞 → 要建模所有凹洞太貴（一顆橘子 100 萬個三角形？）
  4. 拍一張真橘子的照片「貼」到簡單模型上 → 這就是 texture mapping
  5. 還是太光滑？要改變局部形狀 → 用 bump mapping
Texture mapping 種類做法
Texture mapping用影像填滿多邊形內部
Environment mapping用環境的照片當貼圖，模擬高度反光（鏡面）的表面
Bump mapping渲染時改變表面的法向量，產生凹凸感
Texture：像影像一樣的一塊記憶體，最小元素叫 texel；常用來提供表面細節；GPU 有額外的專用硬體處理某些 texture 運算（過濾、取樣）。 texel 和圖片 pixel、螢幕 pixel 的關係見 下方。

texel 和 pixel 的關係：是一一對應嗎？

常被混在一起的有三種「格子」，答案要分兩段看：

關係一一對應？說明
圖檔 pixel → texel
（上傳時）		是（level 0）glTexImage2D / glTexSubImage2D 把圖的每個 pixel 複製成一個 texel：寬 × 高相同、第 (i, j) 個 pixel 就是第 (i, j) 個 texel。只有這些細節會變：
  • 上下順序：圖檔第一列在最上面，texel 的第 0 列在最下面 → 所以要 stbi_set_flip_vertically_on_load(true)。
  • 格式：stbi_load(…, 4) 把 RGB 補成 RGBA；internal format（如 GL_RGBA8、GL_R8）決定每個 texel 存幾個 channel、幾 bit。
  • Mipmap：level 1、2… 的 texel 是 glGenerateMipmap 把 2×2 平均算出來的，圖檔裡沒有對應的 pixel。
texel → 螢幕 pixel
（畫的時候）		不是貼了 texture 的三角形在螢幕上可大可小、可以斜著看，所以：
  • 放大（magnification）：一個 texel 蓋住很多螢幕 pixel → 靠 MAG_FILTER（NEAREST 方塊、LINEAR 平滑）。
  • 縮小（minification）：一個螢幕 pixel 跨過很多 texel → 靠 MIN_FILTER 與 mipmap，不然會閃爍。
  • 每個 fragment 只用它的 uv 去取樣一次（texture 函式），不是「把 texel 一格一格搬到螢幕上」。
剛好 1:1 的特例只有特定情況全螢幕 quad、texture 和 viewport 一樣大（例如作業 2 的 FBO 後製），而且取樣點落在 texel 中心 → 一個螢幕 pixel 剛好對到一個 texel。這時可以直接用 texelFetch(tex, ivec2(gl_FragCoord.xy), 0)。
座標怎麼對：uv vs texel 編號
  • texel 用整數編號 (i, j)：i = 0 ~ 寬−1、j = 0 ~ 高−1（texelFetch 用這個）。
  • uv 是 0 ~ 1 的連續座標（texture 用這個）：uv (0, 0) 是 texel (0, 0) 的左下角，不是中心。
  • texel (i, j) 的中心在 uv = ((i + 0.5) / 寬, (j + 0.5) / 高)。
  • 反過來：uv → uv × 尺寸 − 0.5，整數部分決定 LINEAR 用哪 2×2 個 texel，小數部分是權重；NEAREST 則取 floor(uv × 尺寸) 那一格。

例：寬 4 的 texture，4 個 texel 的中心在 u = 0.125、0.375、0.625、0.875；u = 0.5 剛好在 texel 1 和 2 的交界，LINEAR 會各取一半。

void generate_texture(float* data, int width, int height) {
    for (int y = 0; y < height; y++)
        for (int x = 0; x < width; x++) {
            data[(y * width + x) * 4 + 0] = (float)((x & y) & 0xFF) / 255.0f;
            data[(y * width + x) * 4 + 1] = (float)((x | y) & 0xFF) / 255.0f;
            data[(y * width + x) * 4 + 2] = (float)((x ^ y) & 0xFF) / 255.0f;
            data[(y * width + x) * 4 + 3] = 1.0f;
        }
}

int w, h, n;
stbi_set_flip_vertically_on_load(true);
unsigned char* pixels = stbi_load("assets/brick.png", &w, &h, &n, 4);
// 路徑是相對於「執行時的工作目錄」，不是 .cpp 或執行檔所在的位置

glGenTextures(1, &tex);
glBindTexture(GL_TEXTURE_2D, tex);
glTexImage2D(GL_TEXTURE_2D, 0, GL_RGBA8, w, h, 0,
             GL_RGBA, GL_UNSIGNED_BYTE, pixels);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_WRAP_S, GL_REPEAT);   // u 超出 0~1 時重複
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_WRAP_T, GL_REPEAT);   // v 超出 0~1 時重複
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MIN_FILTER, GL_LINEAR);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MAG_FILTER, GL_LINEAR);
stbi_image_free(pixels);

// render：texture 接到 unit 0，sampler tex_object = 0
glActiveTexture(GL_TEXTURE0);
glBindTexture(GL_TEXTURE_2D, tex);
glUniform1i(glGetUniformLocation(program, "tex_object"), 0);
  • 圖檔路徑：自己在程式裡寫（如上），相對於工作目錄；作業 template 的工作目錄是專案根目錄，所以寫 "assets/xxx.png"。
  • 模型檔指定的路徑：OBJ 旁邊的 .mtl 會寫 map_Kd textures/brick.png，這個路徑是相對於 .obj 所在的資料夾，C++ 要自己接上資料夾名稱（見 AS2 的 Sponza 說明）。
  • Shader 完全不知道檔案路徑；它只透過 tex_object（texture unit 編號）讀 GPU 上的 texture。

③ 不是正規化座標嗎？為什麼可以乘 vec2(3.0, 1.0)

// GLSL：Vertex Shader
#version 410 core
layout (location = 0) in vec4 position;
layout (location = 4) in vec2 tc;
uniform mat4 mv_matrix;
uniform mat4 proj_matrix;
out VS_OUT { vec2 tc; } vs_out;
void main(void)
{
    vec4 pos_vs = mv_matrix * position;
    vs_out.tc = tc;      // 原封傳下去
    gl_Position = proj_matrix * pos_vs;
}
// GLSL：Fragment Shader
#version 410 core
uniform sampler2D tex_object;
in VS_OUT { vec2 tc; } fs_in;
out vec4 color;
void main(void)
{
    // (u, v) → (3u, v)
    vec2 uv = fs_in.tc * vec2(3.0, 1.0);
    color = texture(tex_object, uv);
}
  • 「正規化」的意思：0 ~ 1 剛好對應圖的一整份（u = 0 左邊、u = 1 右邊），和圖是 256 還是 1024 寬無關。它不是限制只能用 0 ~ 1。
  • tc 只是一個普通的 vec2：vec2 * vec2 是逐分量相乘 → (u × 3, v × 1)。u 原本 0 ~ 1，乘完變 0 ~ 3。
  • 超出 0 ~ 1 怎麼辦，由 wrap mode 決定（上面的 GL_TEXTURE_WRAP_S / T）：
    • GL_REPEAT（預設）：只看小數部分 → u = 1.3 讀到 0.3 的位置 → 橫向重複 3 次。
    • GL_MIRRORED_REPEAT：每過一份就左右翻轉一次。
    • GL_CLAMP_TO_EDGE：超出就一直用邊緣那一排 texel → 右邊 2/3 被拉成條紋。
  • 所以「乘 3 → 重複 3 次」要配合 GL_REPEAT；換成 CLAMP_TO_EDGE 就不會重複。

Texture 操作：filtering、mipmap、wrapping、comparison

GPU 有專用硬體做這些 texture 操作；尤其 filtering 對畫質非常重要。這也是 texture 和 buffer 的主要差別：texture 可以被過濾，buffer 不行。

Filtering 的目標

算出一個 fragment 蓋到的所有 texel 的總貢獻。把 fragment 想成房間的一扇窗，你只能用一個顏色描述窗外的景色——理論上最好的答案是所有射入光線的平均色。

正確算平均要用 Monte Carlo 等方法 → 即時渲染太貴。OpenGL 提供簡化、硬體加速的版本：nearest、bilinear、mipmapping、anisotropic。

Magnification vs Minification
  • 放大（一個 texel 蓋好幾個 fragment）：要內插顏色，避免一格一格的方塊感
  • 縮小（一個 fragment 蓋好幾個 texel）：希望一次讀取就拿到所有 texel 的平均 → mipmap
方法做法品質 / 速度
Nearest取最近的 texel最便宜、最差（Minecraft 故意用）
Bilinear2×2 鄰近 texel 內插較慢、較好
Anisotropic依相機投影的形狀取更多樣本可能很慢、最好；看硬體是否支援

互動：隧道地板（同一張貼圖、四種過濾）

講義的 Tunnel 範例：遠處的 texel 比像素小很多（縮小），nearest / bilinear 會產生閃爍的雜訊（aliasing）；mipmap 讀預先縮小的版本，遠處變平滑。

Mipmapping

  • 每一層是上一層 2×2 預先平均的結果，從原尺寸一路到 1×1
  • 縮小時從較小的層取樣：在 level 1 讀 1 個 texel = 在 level 0 讀 4 個
  • 相鄰兩層的結果還可以再內插 → 層與層之間平滑過渡（GL_LINEAR_MIPMAP_LINEAR = trilinear）
  • 所有層總共只多用約 1/3 的記憶體
  • 層數在 glTexStorage2D 的 levels 參數指定；每層可以用 glTexSubImage2D(level, …) 自己上傳，或上傳 level 0 後呼叫 glGenerateMipmap() 自動產生

Wrapping：UV 超出 [0, 1] 時

設定 GL_TEXTURE_WRAP_S 和 GL_TEXTURE_WRAP_T（S、T 就是 U、V）。示意 UV 範圍 [−1, 2]，中間框是 [0, 1]。

GL_CLAMP_TO_BORDER 用 GL_TEXTURE_BORDER_COLOR 設定的顏色（這裡是黑色）。

Texture comparison

取值前先做一次比較：通過回傳 1.0、失敗回傳 0.0，再和 filter 結合後回傳。設定 GL_TEXTURE_COMPARE_MODE、GL_TEXTURE_COMPARE_FUNC。用來加速 shadow mapping。

// C++：用 texture parameter 設定這些操作
glBindTexture(GL_TEXTURE_2D, texture);
// (1) nearest-neighbor filtering
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MAG_FILTER, GL_NEAREST);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MIN_FILTER, GL_NEAREST);
// (2) bilinear filtering
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MAG_FILTER, GL_LINEAR);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MIN_FILTER, GL_LINEAR);
// (3) bilinear filtering with mipmapping
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MAG_FILTER, GL_LINEAR);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MIN_FILTER, GL_LINEAR_MIPMAP_LINEAR);
glGenerateMipmap(GL_TEXTURE_2D);
// wrapping
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_WRAP_S, GL_REPEAT);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_WRAP_T, GL_REPEAT);
常見黑畫面原因：GL_TEXTURE_MIN_FILTER 的預設值是 GL_NEAREST_MIPMAP_LINEAR（需要 mipmap）。沒產生 mipmap 又沒改 filter → texture incomplete → 取樣得到黑色。

參數完整說明：glTexParameter、Sampler Object。

Array texture（範例：Alien Rain）

  • 一個 texture object 裡放很多層貼圖
  • 除了 3D texture，每種 texture 都有 array 版（GL_TEXTURE_2D_ARRAY 等）
  • 可以自訂 texture 資料結構；同時用很多張貼圖時減少 bind 次數
  • 2D array 用 glTexStorage3D / glTexSubImage3D 指定（第三維 = 第幾層）
  • Shader 用 sampler2DArray，texture(tex, vec3(uv, layer))

Alien Rain：256 個外星人往下掉，64 種外星人貼圖放在一個 array texture；每個外星人的位置與旋轉放在 UBO。

// C++：初始化
glGenBuffers(1, &rain_buffer);                       // UBO：256 個 vec4
glBindBuffer(GL_UNIFORM_BUFFER, rain_buffer);
glBufferData(GL_UNIFORM_BUFFER, 256 * sizeof(glm::vec4), NULL, GL_DYNAMIC_DRAW);

glGenTextures(1, &tex_alien_array);
glBindTexture(GL_TEXTURE_2D_ARRAY, tex_alien_array);
glTexStorage3D(GL_TEXTURE_2D_ARRAY, 8, GL_RGBA8, 256, 256, 64);   // depth = 64 層
for (int i = 0; i < 64; i++)
    glTexSubImage3D(GL_TEXTURE_2D_ARRAY, 0, 0, 0, i,   // z offset = 第 i 層
                    256, 256, 1, GL_RGBA, GL_UNSIGNED_BYTE, image_data[i]);

// C++：render
glBindBufferBase(GL_UNIFORM_BUFFER, 0, rain_buffer);
glm::vec4* droplet = (glm::vec4*)glMapBufferRange(GL_UNIFORM_BUFFER, 0,
    256 * sizeof(glm::vec4), GL_MAP_WRITE_BIT | GL_MAP_INVALIDATE_BUFFER_BIT);
for (int i = 0; i < 256; i++) {
    droplet[i][0] = droplet_x_offset[i];
    droplet[i][1] = 2.0f - fmodf((t + float(i)) * droplet_fall_speed[i], 4.31f);
    droplet[i][2] = t * droplet_rot_speed[i];
    droplet[i][3] = 0.0f;
}
glUnmapBuffer(GL_UNIFORM_BUFFER);
for (int alien_index = 0; alien_index < 256; alien_index++) {
    glVertexAttribI1i(0, alien_index);       // 整數 attribute 常數
    glDrawArrays(GL_TRIANGLE_STRIP, 0, 4);   // 一個四邊形
}
// GLSL：Vertex Shader
#version 410 core
layout (location = 0) in int alien_index;
out VS_OUT { flat int alien; vec2 tc; } vs_out;
struct droplet_t { float x_offset; float y_offset; float orientation; float unused; };
layout(std140) uniform droplets { droplet_t droplet[256]; };
void main(void)
{
    const vec2[4] position = vec2[4](vec2(-0.5, -0.5), vec2(0.5, -0.5),
                                     vec2(-0.5,  0.5), vec2(0.5,  0.5));
    vs_out.tc = position[gl_VertexID].xy + vec2(0.5);
    float co = cos(droplet[alien_index].orientation);
    float so = sin(droplet[alien_index].orientation);
    mat2 rot = mat2(vec2(co, so), vec2(-so, co));
    vec2 pos = 0.25 * rot * position[gl_VertexID];
    gl_Position = vec4(pos.x + droplet[alien_index].x_offset,
                       pos.y + droplet[alien_index].y_offset, 0.5, 1.0);
    vs_out.alien = alien_index % 64;   // 第幾層貼圖
}
// GLSL：Fragment Shader
#version 410 core
layout (location = 0) out vec4 color;
uniform sampler2DArray tex_aliens;
in VS_OUT { flat int alien; vec2 tc; } fs_in;
void main(void)
{
    color = texture(tex_aliens, vec3(fs_in.tc, float(fs_in.alien)));
}
flat qualifier

一般情況頂點和 fragment 不是 1:1，每個頂點的資料會在 primitive 上插值給每個 fragment。加上 flat 就不插值：這個 primitive 產生的所有 fragment 都拿到同一個值。整數（如 layer index）不能插值，所以必須 flat。
