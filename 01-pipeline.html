1. Rendering Pipeline

核心觀念Pipeline 互動圖一個三角形的旅程座標空間與 MVP必要數學RasterizerPer-SampleCompute

核心觀念

  • OpenGL 是 API，不是語言：由顯卡 driver（NVIDIA / AMD / Mesa）實作；不管視窗與輸入（交給 GLFW）。
  • State machine：先「設定狀態 / bind 物件」，再下 Draw Command（glDrawArrays / glDrawElements）。設定會一直保留到你改它。
  • API 大致兩類：
    • 指定物件：Buffer（vertex / index）、Texture、Shader Program、Framebuffer Object
    • 設定 pipeline：fixed-function 的開關（depth test、culling…）、目前用哪個 program、render target
  • Object 以 GLuint 識別：glGen* / glCreate* 拿到 ID → glBind* 掛上 pipeline → 操作 → glDelete*。
  • 典型一幀：設定 Object#1 → draw → 設定 Object#2 → draw …；共用設定的物件連續畫可省 API call（省 CPU）。
  • 本課用 Programmable Pipeline（OpenGL 3.0+ core profile；shader 用 #version 410 core）。舊式 fixed-function（glBegin/glEnd）已 deprecated，網路上舊教學別抄。
名詞小辭典
名詞白話解釋
Vertex（頂點）一個點加上它的屬性（位置、顏色、法向量、UV…）。一個三角形 = 3 個 vertex。
Primitive由頂點組成的基本圖形：點、線、三角形。GPU 只會畫這三種，所有 3D 模型都是一堆三角形。
Fragment「候選像素」：三角形蓋到的每個像素產生一個 fragment，帶有插值後的顏色 / 深度。通過 depth test 等檢查後才會真正寫成 pixel。
Shader跑在 GPU 上的小程式，用 GLSL 寫。Vertex shader 每頂點跑一次、Fragment shader 每 fragment 跑一次，成千上萬個同時平行執行。
Buffer / Texture放在 GPU 記憶體的資料。Buffer 像一維陣列（頂點資料），Texture 像圖片（可被 filter 取樣）。
ContextOpenGL 的「執行環境」，記錄所有狀態與物件。GLFW 建視窗時順便建立。
Draw call一次 glDraw* 呼叫 = 叫 GPU 用目前的設定畫一批 primitive。
範例：State machine 是什麼意思？

OpenGL 就像一台有很多開關的機器。glDraw* 不帶「用哪個 shader、哪份資料」的參數，而是用當下開關的狀態。

glUseProgram(redShader);      // 開關：目前 shader = 紅色
glBindVertexArray(cubeVAO);   // 開關：目前資料 = 立方體
glDrawArrays(GL_TRIANGLES, 0, 36);   // 畫出紅色立方體

glBindVertexArray(sphereVAO); // 只換資料，shader 沒改
glDrawArrays(GL_TRIANGLES, 0, 960);  // 畫出「紅色」球 —— 因為 shader 狀態還留著

所以 bug 常來自「狀態殘留」：上一個物件開的設定（如 blending、某張 texture）影響了下一個物件。

為什麼用 GLuint ID？ 物件實際存在 driver / GPU 裡，你手上只有一個編號（像檔案的 file descriptor）。例如 glGenBuffers(1, &vbo) 後 vbo 可能是 1，之後所有操作都用這個 1 指名。

座標空間與 MVP

  • Model：物件擺到世界（translate / rotate / scale）；View：把世界轉到相機座標（lookAt）；Projection：視錐 → clip space（perspective / ortho）。
  • Vertex shader 通常只做 gl_Position = P * V * M * pos;，之後 perspective division（÷w）與 viewport transform 由 Rasterizer 自動做，你只能用 glViewport 設定後者。
  • OpenGL 相機座標是 right-handed、相機看向 -z；Projection 之後 NDC 變成 left-handed（z 越大越遠，範圍 [-1, 1]）。
範例：用「拍照」理解五個步驟
  1. Model：把道具擺到場景中（模型檔裡的茶壺座標以自己為中心，Model 把它移到桌上 (3,1,0) 並轉 90°）。
  2. View：架好相機（相機在 (0,2,5) 看向原點）。數學上是「把整個世界搬動到以相機為原點」。
  3. Projection：選鏡頭（廣角 / 望遠 = FOV），決定哪些東西在畫面內。
  4. ÷w：近大遠小在這一步發生。
  5. Viewport：把照片印成指定大小（800×600 pixel）。

數字走一次：某點在 clip space 是 (2, 1, 3, 4) → NDC = (2/4, 1/4, 3/4) = (0.5, 0.25, 0.75)，三個值都在 [-1,1] 內所以可見。視窗 800×600 時 screen x = (0.5+1)/2×800 = 600、y = (0.25+1)/2×600 = 375（從下往上算）。
同一個點若離相機更遠，w 會更大（perspective 的 w ≈ 到相機的距離）→ 除完 x、y 更接近 0 → 更靠近畫面中心、看起來更小。這就是「近大遠小」。

必要數學（Transformation 講義重點）

Homogeneous coordinate
  • 點 (x,y,z,1)；方向 (x,y,z,0)
  • w=0 → translate 對方向無效（正確行為）
  • 每個 vertex 是 column vector，矩陣前乘：v' = M v
  • OpenGL / GLM 矩陣是 column-major 儲存
組合順序
  • M = T * R * S：先 scale、再 rotate、最後 translate（從右往左讀）
  • MVP = P * V * M
  • 逆矩陣捷徑：T⁻¹(t)=T(-t)、R⁻¹=Rᵀ、S⁻¹(s)=S(1/s)
向量運算
  • dot(A,B)=|A||B|cosθ：夾角、投影、光照 max(dot(N,L),0)
  • cross(A,B)：垂直兩者，右手定則；cross(A,B) = -cross(B,A)
  • 單位向量：normalize(v)
lookAt(E, C, U)
  • F = normalize(C − E)（前）
  • S = normalize(cross(F, U))（右）
  • U' = cross(S, F)（上）
  • View = Rotation * Translation(−E)：移相機 = 反方向移世界
Projection
  • Perspective：遠小近大，perspective(fovy, aspect, near, far)
  • Orthographic：無透視，ortho(l,r,b,t,n,f)
  • near/far 比例別太懸殊（near 太小 → depth 精度差、z-fighting）
Rotation
  • 繞 x/y/z 軸或任意軸 + 角度（GLM 用弧度）
  • Euler angles 有 gimbal lock；需要平滑插值或任意旋轉時用 quaternion
  • Non-uniform scale 會改變法向量方向 → normal 要用 transpose(inverse(M))
範例 1：為什麼要 w？點 vs 方向

平移 (+5, 0, 0) 的矩陣 T，最右邊一欄放位移量。乘上去時，位移會乘以 w：

T = | 1 0 0 5 |      點   p = (1, 2, 3, 1)  →  T·p = (1+5·1, 2, 3, 1) = (6, 2, 3, 1)   ✔ 點被移動
    | 0 1 0 0 |      方向 d = (1, 0, 0, 0)  →  T·d = (1+5·0, 0, 0, 0) = (1, 0, 0, 0)   ✔ 方向不變
    | 0 0 1 0 |
    | 0 0 0 1 |

法向量、光線方向等「方向」本來就不該因物體平移而改變，w=0 剛好自動處理。

範例 2：順序很重要

把點 p = (1, 0, 0) 先「繞 y 軸轉 90°」、再「往 +x 移 5」：

  • T * R * p（先 R 後 T）：轉完變 (0, 0, -1) → 平移得 (5, 0, -1)：物體在原地自轉後搬過去
  • R * T * p（先 T 後 R）：平移得 (6, 0, 0) → 繞原點轉得 (0, 0, -6)：物體跑到很遠的地方（像繞太陽公轉）

規則：離 p 最近（最右邊）的矩陣最先作用。一般物件用 T * R * S。上方互動圖勾「順序改 R·T」可以看到差別。

範例 3：dot / cross 實際用途
  • dot((1,0,0), (0,1,0)) = 0 → 垂直；dot((1,0,0), (1,0,0)) = 1 → 同方向；dot((1,0,0), (-1,0,0)) = -1 → 反向。
  • 光照：法向量 N 與指向光源的 L 都是單位向量時，dot(N, L) 就是亮度比例。光正對表面 = 1（最亮），光斜 60° = 0.5，光從背後 = 負數（用 max(…, 0) 截成 0）。
  • cross((1,0,0), (0,1,0)) = (0,0,1)：x 叉 y 得 z（右手定則）。三角形兩邊做 cross 就得到它的法向量。

Rasterizer（fixed function）內部

  1. Face culling：依頂點順序（預設 CCW = front）丟掉背面。glEnable(GL_CULL_FACE)、glCullFace、glFrontFace
  2. Primitive culling：整個在 view volume 外 → 丟掉
  3. Clipping：部分在外 → 切成新的 primitive（在 clip space 做最有效率）
  4. Perspective division：clip → NDC（÷w），不可控制
  5. Viewport transform：NDC → screen。glViewport、glDepthRange（視窗 resize 時要重設 viewport）
  6. Rasterization：三角形 → fragments；VS 的 out 變數在此被插值後送進 FS 的 in。相關：glPolygonMode（線框）、glPointSize、glLineWidth
  7. Multisampling：硬體 anti-aliasing，GL_MULTISAMPLE
範例：插值（interpolation）

一條邊的兩端，頂點 A 顏色 (1,0,0) 紅、頂點 B 顏色 (0,0,1) 藍。VS 只在 A、B 兩點各跑一次，但中間有很多像素：

  • 距 A 25% 處的 fragment 拿到 0.75·紅 + 0.25·藍 = (0.75, 0, 0.25)
  • 正中間拿到 (0.5, 0, 0.5) 紫色

三角形內部則用三個頂點的 barycentric 權重（加總為 1）混合。任何從 VS out 出來的值（顏色、UV、法向量、世界座標）都會這樣被插值後送進 FS——這就是為什麼 FS 能拿到「每個像素自己的 UV」。上方「一個三角形的旅程」第 5 步就是這個效果。

注意：插值後的法向量長度不再是 1 → FS 裡要再 normalize 一次。

Per-Sample Processing

Test做什麼API
Scissor矩形外的 fragment 丟掉GL_SCISSOR_TEST, glScissor
Stencil和 stencil buffer 比較，做遮罩（可動態更新）GL_STENCIL_TEST, glStencilFunc/Op/Mask
DepthZ-buffer：比較深度決定能否覆蓋GL_DEPTH_TEST, glDepthFunc, glDepthMask
Blending通過測試後與既有顏色混合（半透明）GL_BLEND, glBlendFunc
範例：Depth test 與 Blending 的數字
  • Depth test（GL_LESS）：某像素目前 depth buffer 存 0.6（之前畫的牆）。新 fragment 深度 0.4（比牆近）→ 0.4 < 0.6 通過，寫入顏色並把 depth 更新成 0.4。之後又來一個 0.7 的 fragment（牆後面的東西）→ 0.7 < 0.4 不成立 → 丟掉。結果和繪製順序無關，這就是 Z-buffer 的價值。
  • 沒開 depth test：後畫的永遠蓋掉先畫的 → 牆後面的東西如果比較晚畫，會「穿透」到前面。
  • Blending（glBlendFunc(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA)）：畫面上已有藍色 (0,0,1)，新畫一個 α=0.3 的紅色玻璃 (1,0,0)：
    結果 = 0.3 × (1,0,0) + 0.7 × (0,0,1) = (0.3, 0, 0.7)。
開了 depth test，每幀必須 glClear(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT)，否則上一幀的深度會擋住新畫面。半透明物體通常要先畫不透明、再由遠到近畫透明。

Compute Pipeline

  • OpenGL 4.3+，只有一個 programmable stage，沒有固定輸入輸出，可任意讀寫 buffer / texture（概念近 CUDA）。
  • 用途：粒子 / 布料 / 水面模擬、程序化貼圖、影像處理（blur）、GPU-driven rendering。期末與後段作業會用到。
  • 注意：macOS 只支援到 OpenGL 4.1，沒有 compute shader。
