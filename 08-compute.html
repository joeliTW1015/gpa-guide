講義 08 · Compute Shader and GPU Driven Rendering

Compute Shader 與 GPU-driven Rendering

對應講義 08。重點：compute shader 是什麼、怎麼切工作（invocation / work group / dispatch）、讀寫的資源（image、SSBO）、同步（memory barrier、atomic），最後用它做 GPU-driven rendering。本頁的 C++ / GLSL 都已在 RTX 5060 Ti（OpenGL 4.6）上實測。

本章重點
  • Compute shader：用 GLSL 寫的通用平行程式，不在 graphics pipeline 裡；OpenGL 4.3+，macOS 不支援。
  • 工作切法：invocation（一個執行緒）→ work group（local_size，編譯時固定）→ dispatch（glDispatchCompute 給幾個 group）。每個 invocation 用 gl_GlobalInvocationID 找自己的資料。
  • 輸出只能寫進 image（imageStore）或 SSBO（可讀寫、可放不定長陣列，用 std430 排列）。
  • 這些寫入是 incoherent：下一步要讀之前必須 glMemoryBarrier，bit 選「之後怎麼讀」。
  • 多個 invocation 寫同一個變數 → race condition → 用 atomicAdd。實測：不用 atomic 時 22109 個可見 instance 只數到 22 個。
  • GPU-driven rendering：compute shader 自己做 culling、填 indirect command，CPU 只下一個 glDrawElementsIndirect。

Compute Shader 是什麼

  • 讓你用 OpenGL API + GLSL 寫 GPU 平行程式的通用 shader，限制比 vertex / fragment shader 少。
  • 不是 graphics pipeline 的一部分：沒有頂點、沒有 rasterizer、沒有 fragment，自己決定要算什麼、寫到哪裡。
  • OpenGL 4.3（2012）起支援。Mac 最高只有 4.1 → 不能用。
Compute shaderVertex / Fragment shader
輸入任意位置讀任意位置讀（uniform、texture…）
輸出任意位置寫：buffer 或 image只能寫固定的地方：VS → 下一個 stage、FS → framebuffer 的 pixel
在 pipeline 裡？不在固定的 stage
平行度自己決定（work group 大小、數量）GPU 和 driver 決定
執行緒間共享資料 / 同步可以（同一個 work group 內）不行

講義的程式碼慣例：黃色框 = C++（CPU）、藍色框 = shader（GPU），本頁用註解 // C++、// GLSL 標示；shader 都從 #version 430 core 開始。

同一個 program 裡不能同時有 compute shader 和其他種類的 shader，否則 link 失敗。

Compute Space：Invocation、Work Group、Dispatch

  • Invocation：最小的執行單位（一個執行緒），每個有唯一的 global index，用來找自己要處理的資料。
  • Work group：一格 invocation（1D / 2D / 3D）。同一個 group 內同時執行、可以互相同步；不同 group 彼此獨立。大小寫在 shader 裡，編譯時固定。
  • Dispatch：一格 work group，glDispatchCompute(x, y, z) 每一維至少 1。group 的執行順序不保證。
  • 1D 常用在訊號、2D 在影像、3D 在體積資料——只是方便，不是規定。
// GLSL：一個 work group 1024 × 1 × 1 個 invocation

Image：在 compute shader 裡讀寫貼圖

  • Image = texture 的某一層 mipmap，當成 2D 陣列用：
  • 用整數 pixel 座標存取：imageLoad(img, ivec2)、imageStore(img, ivec2, vec4)。
  • 沒有 filtering、沒有 mipmap（和 texture() 取樣不同）。
  • 不支援 3 個 channel：要用 GL_RGBA32F、GL_RGBA8 這類 4 channel 格式。
  • 不是 writeonly 的 image 一定要寫 format（如 rgba32f）。
// GLSL：把 binding 2 的圖複製到 binding 3
#version 430 core
layout (local_size_x = 16, local_size_y = 16, local_size_z = 1) in;
layout (binding = 2, rgba32f) uniform readonly  image2D srcTex;
layout (binding = 3)          uniform writeonly image2D dstTex;
void main()
{
    ivec2 uv = ivec2(gl_GlobalInvocationID.xy);   // 一個 invocation 處理一個 pixel
    vec4 srcPixel = imageLoad(srcTex, uv);
    imageStore(dstTex, uv, srcPixel);
}

// C++：把 texture 接到 image unit（binding = 第一個參數）
glBindImageTexture(2, srcTex, 0, GL_FALSE, 0, GL_READ_ONLY,  GL_RGBA32F);
glBindImageTexture(3, dstTex, 0, GL_FALSE, 0, GL_WRITE_ONLY, GL_RGBA32F);

每個 invocation 處理一個 pixel：local_size = 16 × 16，所以 512 × 512 要 glDispatchCompute(32, 32, 1)（512 / 16 = 32）。

// GLSL：compute shader
#version 430 core
layout (local_size_x = 16, local_size_y = 16, local_size_z = 1) in;
layout (binding = 2, rgba32f) uniform readonly  image2D srcTex;
layout (binding = 3)          uniform writeonly image2D dstTex;
layout (location = 1) uniform vec4 mouseCursor;   // pixel 座標
void main()
{
    ivec2 uv = ivec2(gl_GlobalInvocationID.xy);
    vec4 srcPixel = imageLoad(srcTex, uv);
    float d = length(uv - mouseCursor.xy);         // 到滑鼠的距離
    float m = max(100.0 - d, 0.0) / 100.0;         // 0 ~ 100 px：1 → 0
    vec4 color = mix(vec4(0.2, 0.2, 0.2, 1.0), srcPixel, m);
    imageStore(dstTex, uv, color);
}

Memory Barrier

  • Compute shader 透過 image store、SSBO 寫的資料是 incoherent 的：之後的讀取不保證看得到新值（甚至之後的寫入也不保證蓋得掉它）。
  • glMemoryBarrier(bits)：保證在它之前發出的 incoherent 寫入，對之後指定種類的讀取可見。
  • bit 選「之後要怎麼用這份資料」，不是「之前怎麼寫的」。
之後要這樣用bit講義哪裡用到
shader 用 SSBO 讀寫GL_SHADER_STORAGE_BARRIER_BIT粒子、reset → collect
shader 用 imageLoad / imageStoreGL_SHADER_IMAGE_ACCESS_BARRIER_BIT
shader 用 texture()（sampler）取樣GL_TEXTURE_FETCH_BARRIER_BIT聚光燈範例
當 vertex attribute（VBO）讀GL_VERTEX_ATTRIB_ARRAY_BARRIER_BITGPU-driven（可見 instance 當 attribute）
當 indirect draw / dispatch 的參數GL_COMMAND_BARRIER_BITGPU-driven（instanceCount）
當 index bufferGL_ELEMENT_ARRAY_BARRIER_BIT
當 uniform bufferGL_UNIFORM_BARRIER_BIT
讀回 CPU：glGetBufferSubData、mapGL_BUFFER_UPDATE_BARRIER_BIT
讀回 CPU：glGetTexImageGL_TEXTURE_UPDATE_BARRIER_BIT
全部GL_ALL_BARRIER_BITS除錯時先用它，確定是同步問題再縮小

Shader Storage Buffer Object（SSBO）

  • 一大塊連續的 GPU 記憶體，shader 可讀也可寫（還能 atomic 寫）。
  • 可以有不定長陣列 data[]，長度看 buffer 實際多大。
  • 和 UBO 比：UBO 唯讀、大小有上限（常見 64 KB）、用 std140；SSBO 可寫、大很多、用 std430。
  • 每個 block 只能有一個不定長陣列，而且要放最後。
block 內容
int foo; float data[]; float data1[];✗ 兩個不定長
int foo; float data[]; float data1[2];✗ 不定長不在最後
int foo; float data[2]; float data1[];✓
// GLSL：binding 3 的 SSBO，一個 int + 不定長 float 陣列
layout (std430, binding = 3) buffer LayoutName {
    int   foo;
    float data[];
};

// C++：建立並接到 binding point 3
GLuint ssbo;
glGenBuffers(1, &ssbo);
glBindBuffer(GL_SHADER_STORAGE_BUFFER, ssbo);
glBufferStorage(GL_SHADER_STORAGE_BUFFER,
                sizeof(int) + N * sizeof(float),
                nullptr, GL_DYNAMIC_STORAGE_BIT);  // 之後要 glBufferSubData
glBufferSubData(GL_SHADER_STORAGE_BUFFER, 0,
                sizeof(int), &foo);                 // foo 在 offset 0
glBufferSubData(GL_SHADER_STORAGE_BUFFER, sizeof(int),
                N * sizeof(float), data);            // data 從 offset 4 開始
glBindBufferBase(GL_SHADER_STORAGE_BUFFER, 3, ssbo);

// 陣列裡放 struct 也可以
struct SSBO_DATA { int data0; float data1; };
layout (std430, binding = 3) buffer LayoutName {
    SSBO_DATA data[];
};

binding = 3 和 UBO 一樣是「插座」編號：C++ 的 glBindBufferBase(GL_SHADER_STORAGE_BUFFER, 3, ssbo) 把 buffer 插到 3 號，shader 的 block 從 3 號讀（UBO 的插座概念見 講義 04）。glBufferStorage 是 4.4 的函式，也可以用 glBufferData。

std430 排列規則：C++ struct 要對得上

SSBO 裡每個變數的 byte 位置由 std430 決定；C++ 端 memcpy 進去的 struct 必須每個欄位的 offset 都一樣，否則 shader 讀到錯位的資料。

型別大小對齊（offset 必須是它的倍數）

範例：粒子模擬（黑洞）

SSBO：粒子position、velocity、color、properties（life）
⇄
Compute shader每個 invocation 更新一顆粒子
uniform：滑鼠 = 黑洞
→
VS + FSglDrawArrays(GL_POINTS)，VS 用 gl_VertexID 讀同一個 SSBO
// GLSL：compute shader（講義）
#version 430 core
layout (local_size_x = 1024, local_size_y = 1, local_size_z = 1) in;
struct ParticleProties {
    vec4 position;
    vec4 velocity;
    vec4 color;
    vec4 properties;   // x: 壽命, y: 剩餘壽命（全用 vec4 → 不踩 vec3 的坑）
};
layout (std430, binding = 1) buffer ParticleData {
    ParticleProties particleProps[];
};
layout (location = 3) uniform vec4 mouseCursor;

float virtualRand(vec2 v)   // 回傳 -1 ~ 1（講義註解寫 [0, 1) 是錯的）
{
    return fract(sin(dot(v, vec2(12.9898, 78.233))) * 43758.5453) * 2.0 - 1.0;
}

void main()
{
    const uint IDX = gl_GlobalInvocationID.x;
    vec3 pos = particleProps[IDX].position.xyz;
    vec3 vel = particleProps[IDX].velocity.xyz;
    float life = particleProps[IDX].properties.y;
    if (life <= 0.0) {                          // 壽命到了 → 隨機位置重生
        pos.x = virtualRand(pos.xy); pos.y = virtualRand(vel.xy);
        vel.x = 0.0; vel.y = 0.0;
        particleProps[IDX].properties.x = (virtualRand(pos.xy) + 1.1) * 5.0;
        life = particleProps[IDX].properties.x;
    }
    // 黑洞的引力：大小 100 / 距離，方向指向滑鼠
    vec3 center = vec3(mouseCursor.xy, 0.0);
    float dis = length(center - pos);
    vec3 dir = normalize(center - pos);
    float forceMagnitude = 0.0;
    if (dis > 0.00001) forceMagnitude = 100.0 / dis;   // 避免除以 0
    vec3 force = forceMagnitude * dir;
    // Euler 積分
    const float PARTICLE_INV_MASS = 1.0 / 0.1;
    const float DELTA_TIME = 0.00002;
    vec3 acl = force * PARTICLE_INV_MASS;
    vec3 npos = pos + vel * DELTA_TIME + 0.5 * acl * DELTA_TIME * DELTA_TIME;
    vec3 nvel = vel + acl * DELTA_TIME;
    particleProps[IDX].position.xyz = npos;
    particleProps[IDX].velocity.xyz = nvel * 0.99993;   // 阻尼
    particleProps[IDX].properties.y = life - DELTA_TIME;
}
// GLSL：vertex shader，直接讀同一個 SSBO
#version 430 core
out vec4 f_color;
struct ParticleProties { vec4 position; vec4 velocity; vec4 color; vec4 properties; };
layout (std430, binding = 1) buffer ParticleData { ParticleProties particleProps[]; };
void main()
{
    ParticleProties p = particleProps[gl_VertexID];
    float alpha = p.properties.y / p.properties.x;   // 剩餘壽命比例
    f_color = vec4(p.color.xyz, alpha);
    gl_Position = p.position;                        // 已經是 NDC
}
// GLSL：fragment shader
in vec4 f_color;
layout (location = 0) out vec4 fragColor;
void main() { fragColor = f_color; }
// C++
const int NUM_PARTICLE = 1024 * 128;
// 初始化：粒子資料 → SSBO（binding 1），再建一個空的 VAO
glBufferStorage(GL_SHADER_STORAGE_BUFFER,
                NUM_PARTICLE * sizeof(ParticleProties), pp, GL_MAP_READ_BIT);
glBindBufferBase(GL_SHADER_STORAGE_BUFFER, 1, particleSSBO);
glGenVertexArrays(1, &vao);

// 每幀
glUseProgram(updateCSProgram);
glUniform4fv(3, 1, mouseCursor);
glDispatchCompute(128, 1, 1);                    // 128 × 1024 = 131072 顆
glMemoryBarrier(GL_SHADER_STORAGE_BARRIER_BIT);  // VS 接著要讀 SSBO

逐步動畫（拉視野方向、看三個 buffer 怎麼變）在 講義 07：GPU 收集可見 instance；DrawElementsIndirectCommand 各欄位見 Indirect Draw。

// GLSL：CS #1，reset（只有一個 invocation）
#version 430 core
layout (local_size_x = 1, local_size_y = 1, local_size_z = 1) in;
struct DrawCommand {
    uint count; uint instanceCount; uint firstIndex;
    uint baseVertex; uint baseInstance;
};
layout (std430, binding = 3) buffer DrawCommandsBlock {
    DrawCommand commands[];
};
void main()
{
    commands[gl_LocalInvocationID.x].instanceCount = 0;
}
// GLSL：CS #2，在 clip space 做 frustum culling
// （struct / 三個 SSBO 的宣告同上）
uniform int numMaxInstance;
uniform mat4 viewProjMat;
void main()
{
    const uint idx = gl_GlobalInvocationID.x;
    if (idx >= numMaxInstance) return;     // 最後一個 group 會多出來
    vec4 c = viewProjMat * vec4(rawInstanceProps[idx].position.xyz, 1.0);
    c = c / c.w;                               // → NDC
    bool culled = c.x < -1.0 || c.x > 1.0 || c.y < -1.0
               || c.y > 1.0 || c.z < -1.0 || c.z > 1.0;
    if (!culled) {
        // 拿一個「沒人用過」的位置，同時把 instanceCount + 1
        const uint UNIQUE_IDX = atomicAdd(commands[0].instanceCount, 1);
        currValidInstanceProps[UNIQUE_IDX] = rawInstanceProps[idx];
    }
}

只檢查 instance 的中心點：草根在畫面邊緣外一點點就被丟掉，邊緣可能看到草突然消失。實務上會用 bounding sphere / AABB 加一點邊界。

Race Condition 與 atomicAdd

講義先寫的版本：

// GLSL：錯誤寫法
const uint TARGET_IDX = commands[0].instanceCount;     // ① 讀
currValidInstanceProps[TARGET_IDX] = rawInstanceProps[idx];  // ② 寫資料
commands[0].instanceCount = commands[0].instanceCount + 1;   // ③ 寫回 +1
  • 上千個 invocation 同時執行 ①：大家讀到同一個值 → 寫進同一格、把同一個值 +1 寫回 → 很多次累加被蓋掉。
  • Atomic operation：「讀 → 改 → 寫」一次做完，中間不會被別人插進來。
  • uint atomicAdd(inout uint mem, uint data)：把 data 加到 mem，回傳加之前的值 → 每個 invocation 拿到不同的位置。GLSL 4.3+，mem 必須是 SSBO 或 shared 變數。

// C++：初始化 VAO，可見 instance 的 buffer 當 attribute 3
glGenVertexArrays(1, &vao);

// … 綁草的 VBO（location 0~2）和 IBO

glBindVertexArray(0);

// draw command 的 SSBO（binding 3），instanceCount 先填 0
DrawElementsIndirectCommand cmd = { numIndices, 0, 0, 0, 0 };
glBufferStorage(GL_SHADER_STORAGE_BUFFER, sizeof(cmd), &cmd, GL_MAP_READ_BIT);
glBindBufferBase(GL_SHADER_STORAGE_BUFFER, 3, cmdBuffer);
// C++：每幀
glUseProgram(resetCS);
glDispatchCompute(1, 1, 1);
glMemoryBarrier(GL_SHADER_STORAGE_BARRIER_BIT);     // CS #2 要讀寫 SSBO

glUseProgram(cullingCS);
glUniform1i(locNumMax, NUM_TOTAL_INSTANCE);
glUniformMatrix4fv(locViewProj, 1, GL_FALSE, glm::value_ptr(P * V));
glDispatchCompute((NUM_TOTAL_INSTANCE + 1023) / 1024, 1, 1);
glMemoryBarrier(GL_COMMAND_BARRIER_BIT              // instanceCount 當 draw 參數
              | GL_VERTEX_ATTRIB_ARRAY_BARRIER_BIT); // 可見 instance 當 attribute

glUseProgram(renderProgram);
glBindVertexArray(vao);
glBindBuffer(GL_DRAW_INDIRECT_BUFFER, cmdBuffer);   // 同一個 buffer 換個身份

// CPU 從頭到尾不知道畫了幾個 instance
// GLSL：render 的 vertex shader（per-instance 位移從 attribute 3 來）
layout (location = 0) in vec3 v_vertex;
layout (location = 3) in vec4 v_worldPosOffset;
uniform mat4 projMat, viewMat, modelMat;
void main()
{
    vec4 worldVertex = modelMat * vec4(v_vertex, 1.0) + v_worldPosOffset;
    worldVertex.w = 1.0;   // 兩個 w 都是 1 → 相加變 2，要改回 1
    gl_Position = projMat * viewMat * worldVertex;
}

在作業 template 上用 compute shader

template 不能直接用：context 是 4.1，而且附的 GLAD 只產生到 OpenGL 3.3（builder/external/glad/include/glad/glad.h 開頭寫 APIs: gl=3.3）→ 連 glDispatchCompute 這個函式都沒有，編譯就失敗。
  1. 換 GLAD：到 glad.dav1d.de 選 Language C/C++、gl 4.6、Profile Core、勾 Generate a loader → 下載後替換 builder/external/glad/ 的 glad.h、glad.c（khrplatform.h 一起換）。
  2. 改 context 版本：glfwWindowHint(GLFW_CONTEXT_VERSION_MINOR, 1) → 3（要 glBufferStorage 就用 4.4 以上，或改用 glBufferData）。
  3. Shader 寫 #version 430 core；ImGui 的 glsl_version 不用改。
  4. macOS 沒辦法：最高 4.1，只能在 Windows / Linux 上跑。

本頁的實測程式沒有用 template 的 GLAD，而是在 Linux 直接用系統的 GL/glcorearb.h + libOpenGL.so（4.6 context）。
