講義 02 · OpenGL Overview

OpenGL 概觀

OpenGL 是什麼、從哪裡來、它在乎什麼、不在乎什麼；以及寫一支 OpenGL 程式時，周邊有哪些函式庫（GLU、GLUT、GLFW）負責視窗與輸入。

本章重點
  • OpenGL = Open Graphics Library，是一套跨平台的繪圖 API（不是語言、不是作業系統功能），由顯卡廠商在 driver 裡實作。
  • 它只管「畫圖」：不管視窗、不管輸入。視窗與鍵盤滑鼠交給 GLUT / GLFW（本課用 GLFW）。
  • OpenGL 是一台 state machine：API 分兩類——「建立物件」（buffer、texture、shader、FBO）與「設定 pipeline」（fixed-function 開關、目前用哪個 program、畫到哪裡）。
  • OpenGL 3.0 起 fixed-function pipeline 被淘汰，改用 programmable pipeline：用 GLSL 寫 shader 自訂某些 stage。

About OpenGL
  • Open Graphics Library 的縮寫
  • 一套繪圖渲染 API，用來存取顯示卡的硬體功能
  • 超過 500 個指令，用來指定影像、貼圖、物件與 shader program
  • 用來製作互動式 3D 電腦圖學應用程式
設計理念與實作者
  • 設計成：精簡、與硬體無關的 API；以 primitive（點、線、三角形）為基礎的 rendering pipeline；client-server 架構（你的程式是 client，GPU / driver 是 server）
  • 誰實作：顯卡廠商為每種硬體 / 作業系統實作（NVIDIA、AMD）；作業系統提供軟體渲染版本（如 Mesa）；甚至你自己（電腦圖學 CS5500 會寫一個）

歷史與版本

SGI 與 GL

Silicon Graphics（SGI）在 1982 年把 graphics pipeline 做進硬體，徹底改變了繪圖工作站。工程師為它寫了一套叫 GL 的函式庫，大幅簡化 3D 互動程式的開發。

OpenGL 的誕生（1992）

GL 的成功促成了跨平台的 OpenGL：

  • 容易使用
  • 專注在渲染
  • 夠貼近硬體，效能好
  • 不包含視窗與輸入，避免依賴特定視窗系統
演進方式
  • 原本由 ARB（Architecture Review Board：SGI、Microsoft、NVIDIA、HP、3DLabs、IBM 等）維護，後來由 Khronos Group 接手
  • 版本演進反映新的硬體能力（3D texture、texture object、vertex program…）
  • 透過 extension 讓廠商提供平台特有的新功能
  • 目前穩定版本：4.6
本課用的版本
  • Context：OpenGL 4.1 core profile（macOS 最高支援 4.1）
  • Shader 開頭：#version 410 core
  • 需要 4.3+ 的功能（compute shader、SSBO、multi-draw indirect）會特別標註

進入 3D 世界前要準備的東西

座標系（Cartesian）

畫東西的空間：3D 的 world / local 座標，以及 2D 的螢幕座標。OpenGL 用右手系、y 朝上。詳見 講義 01。

3D Primitives

有「三個維度」量測的物體。GPU 最終只畫點、線、三角形；所有模型都是一堆三角形。

相機（Viewing Camera）

正交：線段投影後長度與距離無關。透視：越遠越小。詳見 Projection。

3D Transformations

Translation、rotation、scaling，把物體擺到正確的位置。詳見 Model 矩陣。

Material & Lighting

顏色、貼圖、shading 等，讓表面看起來像真的材質。

Render to Frame-Buffer

最後把結果畫進 framebuffer，顯示在螢幕上（或畫進 texture 做後製，見 講義 06）。

OpenGL 在乎什麼：State Machine

OpenGL 像一台有很多開關和插槽的機器。你先設定狀態（插上資料、扳好開關），再下 draw command；機器就用當下的狀態畫圖。API 大致分成兩類：

APIs to Specify Objects（建立物件）
  • Vertex / Index Buffers
  • 1D、2D、3D Textures
  • Shader Programs
  • Framebuffer Objects

→ 詳見 講義 04 OpenGL Objects

APIs to Configure the Pipeline（設定 pipeline）
  • Fixed-function stage 的狀態（depth test、culling、blending…）
  • 目前使用哪個 shader program
  • 目前畫到哪個 render target

→ 詳見 講義 03 Rendering Pipeline

  • OpenGL 物件以 GLuint 識別：glGen* / glCreate* 拿到 ID → glBind* 掛上 pipeline → 操作 → glDelete*。
  • 典型一幀：設定 Object#1 → draw → 設定 Object#2 → draw …；共用設定的物件連續畫可以少呼叫幾次 API（省 CPU）。
範例：State machine 是什麼意思？

glDraw* 不帶「用哪個 shader、哪份資料」的參數，而是用當下開關的狀態：

glUseProgram(redShader);      // 開關：目前 shader = 紅色
glBindVertexArray(cubeVAO);   // 開關：目前資料 = 立方體
glDrawArrays(GL_TRIANGLES, 0, 36);   // 畫出紅色立方體

glBindVertexArray(sphereVAO); // 只換資料，shader 沒改
glDrawArrays(GL_TRIANGLES, 0, 960);  // 畫出「紅色」球 —— 因為 shader 狀態還留著

所以 bug 常來自「狀態殘留」：上一個物件開的設定（blending、某張 texture）影響了下一個物件。

為什麼用 GLuint ID？物件實際存在 driver / GPU 裡，你手上只有一個編號（像檔案的 file descriptor）。例如 glGenBuffers(1, &vbo) 後 vbo 可能是 1，之後所有操作都用這個 1 指名。

名詞小辭典
名詞白話解釋
Vertex（頂點）一個點加上它的屬性（位置、顏色、法向量、UV…）。一個三角形 = 3 個 vertex。
Primitive由頂點組成的基本圖形：點、線、三角形。GPU 只會畫這三種。
Fragment「候選像素」：三角形蓋到的每個像素產生一個 fragment，帶有插值後的顏色 / 深度。通過 depth test 等檢查後才會真正寫成 pixel。
Shader跑在 GPU 上的小程式，用 GLSL 寫。Vertex shader 每頂點跑一次、Fragment shader 每 fragment 跑一次，成千上萬個同時平行執行。
Buffer / Texture放在 GPU 記憶體的資料。Buffer 像一維陣列（頂點資料），Texture 像圖片（可被 filter 取樣）。
ContextOpenGL 的「執行環境」，記錄所有狀態與物件。GLFW 建視窗時順便建立。
Draw call一次 glDraw* 呼叫 = 叫 GPU 用目前的設定畫一批 primitive。

Fixed-Function vs Programmable Pipeline

Pipeline：由多個 stage 組成，資料流進來、在每個 stage 被處理、再流出去。Fixed-function stage 只能調整有限的狀態；programmable stage 可以放自己寫的 shader，自由度高很多。

Fixed-function（legacy）：一台很多按鈕的機器

OpenGL 3.0 以前的做法。可以設定很多開關與數值，但無法改變功能怎麼實作、也無法改變執行順序。

比喻：面對一台按鈕超多的機器——「要按哪些按鈕才能得到我要的效果？」

Programmable：自己寫程式產生效果

Shader 在 OpenGL 2.0 引入，3.0 納入 core profile；fixed-function 從 3.0 起被淘汰。用 GLSL（OpenGL Shading Language）自訂 pipeline 中的某些 stage。

比喻：「來寫個程式做出這個效果吧！」

Programmable PipelineFixed-Function Pipeline
彈性＋ 可以在 shader 裡實作各種演算法－ 客製化能力有限
簡單的應用－ 必須設定整條 pipeline＋ 設定少就能完成簡單任務
複雜的應用＋ 可以做出各種效果－ 多數進階效果做不到
學習曲線－ 要先完整了解 pipeline 和 GLSL 才能寫＋ 不太懂也能寫出簡單程式
部署－ 要考慮各種顯卡 driver 環境＋ 幾乎所有 driver 都能跑
網路上很多舊教學用 glBegin / glEnd、glVertex3f、glTranslatef、glPushMatrix——那是 fixed-function，本課（和作業）禁止使用，用了直接 0 分。

周邊函式庫：誰負責什麼

函式庫功能本課
GL（OpenGL core）繪圖本身。Windows 是 OpenGL32、Unix / Linux 多是 libGL使用（core profile）
GLU（OpenGL Utility Library）用 GL 實作的常用工具，免得重寫：NURBS、tessellator、quadric 形狀（球、圓柱）等不用（大多是 fixed-function 時代的東西；矩陣改用 GLM）
GLX / WGL / AGL把 OpenGL 接到 X Window / Windows / Macintosh 的視窗系統由 GLFW 幫你處理
GLUT（OpenGL Utility Toolkit，現在用 freeglut）建立視窗、註冊 callback（render、resize、鍵盤滑鼠）、進入事件迴圈不用
GLFW（Graphics Library Framework）GLUT 的替代品，支援 macOS；同樣負責視窗、context、輸入使用（見 程式骨架）
GLAD在執行時載入 OpenGL 函式指標（講義 Appendix）使用
GLUT 的 callback

「發生某件事時要呼叫的函式」，先註冊給 GLUT：

glutDisplayFunc(display);    // 需要重畫時
glutIdleFunc(idle);          // 沒事做時（做動畫）
glutKeyboardFunc(keyboard);  // 按鍵時
GLFW 的對應寫法（本課） 
glfwSetKeyCallback(window, key_callback);
glfwSetCursorPosCallback(window, cursor_callback);
glfwSetFramebufferSizeCallback(window, resize_callback);
// 重畫和動畫：自己寫 while 迴圈，每圈畫一次
