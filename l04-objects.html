講義 04 · OpenGL Objects

OpenGL Objects：資料怎麼送進 GPU

OpenGL 把資料傳給 GPU 的三種管道：Buffer（大量的頂點 / index / 結構資料）、Uniform（一次 draw call 內不變的參數）、Texture（可以被過濾取樣的影像）。

本章重點
  • Buffer 是一段線性記憶體；用途由它綁到哪個 binding point決定（GL_ARRAY_BUFFER、GL_ELEMENT_ARRAY_BUFFER、GL_UNIFORM_BUFFER…）。glGenBuffers 只產生名字，第一次 bind 才真正建立物件。
  • glBufferData 配置（並可初始化）、glBufferSubData 更新部分、glMapBuffer 直接寫記憶體；它們都作用在目前綁在那個 binding point 上的 buffer。
  • Uniform 在一次 draw 中對所有 shader 呼叫都相同。Default block uniform 存在 program 裡：glGetUniformLocation → glUseProgram → glUniform*。
  • Uniform block（UBO）把 uniform 存在 buffer 裡：block ↔ uniform binding point ↔ buffer；記憶體要照 std140 對齊。
  • Texture 透過 texture image unit 接到 shader：glActiveTexture(GL_TEXTUREn) + glBindTexture，sampler uniform 存的是 unit 編號 n，不是 texture ID。
  • Texture 和 buffer 最大的差別：texture 可以被過濾（nearest、bilinear、mipmap、anisotropic）和包裹（wrap）。

回顧講義 02：OpenGL 是 state machine，API 分成「建立物件」與「設定 pipeline」兩類。本章講的就是第一類中的 buffer、uniform、texture。Resource object（buffer、texture）存的可能是幾何資料、貼圖、查表或中間的渲染結果。

Buffer

Buffer 是什麼
  • 一段線性配置的記憶體，可能在主記憶體或顯示卡記憶體
  • 依用途分類：vertex buffer、index buffer、uniform buffer、shader storage buffer…
  • 所有種類的建立和上傳方式都一樣，差別只在綁到哪個 binding point
種類內容與用途
Vertex / Index每個頂點的輸入（位置 XYZ、UV…），像陣列；由 Vertex Specification stage 讀取，組成 VS 的輸入
Uniform一次 draw 內不變、GPU 唯讀最佳化；每個 shader 呼叫看到同樣內容。比較像 struct：相機設定、光源位置
Shader Storage（SSBO）像 uniform buffer，但 shader 可讀寫的自訂型別陣列；4.3+，講義 07 用到

建立 buffer object 的四步驟（互動）

重點：glGenBuffers 只拿到一個名字（unsigned int），buffer object 還不存在；第一次 glBindBuffer 才建立物件；glBufferData 才配置記憶體。

Binding point（binding target）

OpenGL 用 buffer 的方式由它綁在哪裡決定。要把 buffer 接到 pipeline、或對它做任何操作，都必須先綁到一個 binding point。（講義：Please pay attention to this!）

Buffer 資料：配置、更新、映射

函式做什麼特性
glBufferData(target, size, data, usage)建立新的資料儲存空間，size bytes；data 不是 NULL 就拿它初始化舊的空間會被釋放；可以只配置（data = NULL）
glBufferSubData(target, offset, size, data)從 byte offset 開始，把 size bytes 換成 data 的內容更新部分或全部，比 glBufferData 快
glMapBuffer(target, access) / glUnmapBuffer把整個 buffer 映射到 CPU 位址空間，直接讀寫；unmap 時改動才生效access：GL_READ_ONLY / GL_WRITE_ONLY / GL_READ_WRITE
// C++：三個函式都作用在「目前綁在該 binding point 上的 buffer」
// bind Buffer Object "buffer" to the "GL_ARRAY_BUFFER" Binding Point
glBindBuffer(GL_ARRAY_BUFFER, buffer);
// manipulate the buffer bound to "GL_ARRAY_BUFFER", which is "buffer"
glBufferData(GL_ARRAY_BUFFER, sizeof(data), data, GL_STATIC_DRAW);

// 先配置 1 MB 空的，之後再填
glBufferData(GL_ARRAY_BUFFER, 1024 * 1024, NULL, GL_STATIC_DRAW);
glBufferSubData(GL_ARRAY_BUFFER, 0, sizeof(data), data);

// 或用 map：拿到指標直接寫
void* ptr = glMapBuffer(GL_ARRAY_BUFFER, GL_WRITE_ONLY);
memcpy(ptr, data, sizeof(data));
glUnmapBuffer(GL_ARRAY_BUFFER);   // 告訴 OpenGL 寫完了
glMapBuffer 一定比較快嗎？

可能比 glBufferSubData 快：例如載入模型檔時，不用先自己配置一塊記憶體再呼叫 glBufferSubData，可以直接把檔案內容讀進 glMapBuffer 回傳的記憶體（少一次複製）。

不一定！要看顯示卡 driver 怎麼實作這個函式（講義：Not always True）。

Uniform

什麼是 uniform
  • 宣告在 shader 裡、讓應用程式直接把資料傳給 shader的變數
  • 叫 uniform 是因為在一次 draw command 中保持不變：不能被修改、每個 shader 呼叫讀到相同內容
  • 常放：相機 projection 矩陣、光源設定、texture sampler
  • 存在針對「同步唯讀存取」最佳化的特殊硬體記憶體
兩種機制Default block uniformBuffer-backed uniform block
出現OpenGL 2.0（舊）OpenGL 3.1
資料存在shader program objectbuffer object（UBO）
更新一個一個 glUniform*一次 glBufferSubData 更新全部
多個 program 共用不行，每個 program 各自設定綁到同一個 binding point 就共用

Default block uniform

// GLSL：支援內建型別與自訂 struct
struct MyType
{
    float var1;
    int   var2;
};
uniform float  float_uniform;
uniform int    int_uniform;
uniform vec4   vec4_uniform;
uniform mat4   mat4_uniform;
uniform MyType type_uniform;
同名宣告 = 同一個變數

Uniform 宣告在所有 programmable stage 間共用；同樣的宣告指向同一份資料。只需要在用到它的 stage 宣告。點 uniform 名稱看哪些是同一個：

存在 program 裡的狀態
  • Default block uniform 是 shader program object 的狀態
  • 更新 uniform 值之前要先 bind（glUseProgram）program
  • 值會一直存在 program 裡 → 沒變的值不用每幀重設
  • 每個 uniform 在 program 中用一個 uniform location（整數）識別
使用步驟
  1. 在 shader 程式碼宣告 uniform
  2. 編譯、attach、link shader program
  3. 用 glGetUniformLocation() 取得每個 uniform 的 location
  4. 用 glUseProgram() bind program
  5. 用 glUniform*() 更新某個 location 的值
  6. 發出 draw command

glUniform* 的命名規則

寫法意思例子
glUniform{1|2|3|4}{f|i|ui}(loc, v0, v1, …)數字 = 幾個分量；f / i / ui = float / int / unsigned int；直接傳值glUniform3f(loc, 1, 0.5, 0) → vec3
glUniform{1|2|3|4}{f|i|ui}v(loc, count, ptr)結尾 v = 傳指標；count = 陣列元素數（非陣列填 1）glUniform3fv(loc, 1, &color[0])
glUniformMatrix{2|3|4|2x3|…}fv(loc, count, transpose, ptr)矩陣；transpose = 是否轉置（GLM 是 column-major → GL_FALSE）glUniformMatrix4fv(loc, 1, GL_FALSE, glm::value_ptr(M))

Uniform location 的排列

一般來說，uniform 陣列佔用連續的 location。下面三種寫法效果相同：

// GLSL
uniform float array[3];

// C++ 寫法 1：location 遞增
GLint loc = glGetUniformLocation(myShader, "array[0]");
glUseProgram(myShader);
glUniform1f(loc,     1.0f);
glUniform1f(loc + 1, 2.0f);
glUniform1f(loc + 2, 3.0f);
// C++ 寫法 2：一次傳整個陣列
GLint loc = glGetUniformLocation(myShader, "array[0]");
glUseProgram(myShader);
float data[] = { 1.0f, 2.0f, 3.0f };
glUniform1fv(loc, 3, data);   // count = 3
// C++ 寫法 3：每個元素各查一次
GLint loc[3];
loc[0] = glGetUniformLocation(myShader, "array[0]");
loc[1] = glGetUniformLocation(myShader, "array[1]");
loc[2] = glGetUniformLocation(myShader, "array[2]");
glUseProgram(myShader);
glUniform1f(loc[0], 1.0f);
glUniform1f(loc[1], 2.0f);
glUniform1f(loc[2], 3.0f);

矩陣會佔更多 location！一個 mat4 佔 4 個（每個 column 一個）：

// GLSL

// C++
GLint loc = glGetUniformLocation(myShader, "array");
glUseProgram(myShader);
glUniformMatrix4fv(loc,     1, GL_FALSE, mat1);
glUniformMatrix4fv(loc + 4, 1, GL_FALSE, mat2);   // 不是 loc + 1！
glUniformMatrix4fv(loc + 8, 1, GL_FALSE, mat3);

為了避免 location 算錯：每個 uniform 都用 glGetUniformLocation() 查，或改用 buffer-backed uniform block。

Buffer-backed Uniform Block（UBO）

  • 把一組 uniform 組成一個 uniform block，整個 block 存在一個 buffer object 裡（buffer-backed）
  • 宣告方式像 interface block，但用 uniform 修飾
  • 各 stage 的 block 對應規則和 default block 一樣：同樣的宣告指向同一份資料（同一個 buffer）
  • Program 中的 block 用 uniform block index 識別（glGetUniformBlockIndex）
  • Block 和 buffer 透過綁到同一個 uniform binding point 連起來
// GLSL：宣告名為 TransformBlock 的 uniform block
uniform TransformBlock
{
    float scale;
    vec3  translation;
    float rotation[3];
    mat4  projection_matrix;
} transform;

void main()
{
    // 用 instance 名稱存取
    float s = transform.scale;
}

互動：Uniform binding point

// GLSL
uniform X { float a; mat4 b; };
uniform Y { int c; ivec4 d; };
uniform Z { mat4 e[10]; };
// C++：block → binding point
GLuint X_index = glGetUniformBlockIndex(program, "X");
GLuint Y_index = glGetUniformBlockIndex(program, "Y");
GLuint Z_index = glGetUniformBlockIndex(program, "Z");
glUniformBlockBinding(program, X_index, 1);
glUniformBlockBinding(program, Y_index, 3);
glUniformBlockBinding(program, Z_index, 0);
// C++：buffer → binding point
glBindBufferBase(GL_UNIFORM_BUFFER, 0, buffer_b);   // Z 的資料
glBindBufferBase(GL_UNIFORM_BUFFER, 1, buffer_c);   // X 的資料
glBindBufferBase(GL_UNIFORM_BUFFER, 3, buffer_a);   // Y 的資料
函式做什麼
glGetUniformBlockIndex(program, name)查 uniform block 在 program 中的 index
glUniformBlockBinding(program, blockIndex, binding)指定這個 block 讀哪個 uniform binding point
glBindBufferBase(target, index, buffer)把 buffer 綁到 indexed binding point（GL_UNIFORM_BUFFER 或 GL_TRANSFORM_FEEDBACK_BUFFER）的第 index 個；同時也綁到該 target 的一般 binding point，之後 glBufferSubData / glMapBuffer 會作用在它上面
為什麼用 UBO：更新所有 uniform 只要一次 glBufferSubData()；多個 program 共用同一份資料（例如相機矩陣）時，綁到同一個 binding point 就好。

Texture

幾何建模的極限

現代顯卡每秒能畫超過 100 億個三角形，但只靠幾何，很多擬真的場景還是不夠細。

例：做一顆橘子

  1. 橘色的球 → 太簡單
  2. 換更複雜的形狀 → 抓不到表面特徵
  3. 加上小凹洞 → 要建模所有凹洞太貴（一顆橘子 100 萬個三角形？）
  4. 拍一張真橘子的照片「貼」到簡單模型上 → 這就是 texture mapping
  5. 還是太光滑？要改變局部形狀 → 用 bump mapping
Texture mapping 種類做法
Texture mapping用影像填滿多邊形內部
Environment mapping用環境的照片當貼圖，模擬高度反光（鏡面）的表面
Bump mapping渲染時改變表面的法向量，產生凹凸感
Texture：像影像一樣的一塊記憶體，最小元素叫 texel；常用來提供表面細節；GPU 有額外的專用硬體處理某些 texture 運算（過濾、取樣）。

Texture Image Unit：texture 怎麼接到 shader

Texture object 的使用步驟（和 buffer 很像）
  1. glGenTextures() 產生名字
  2. glBindTexture() 綁到 texture binding target
  3. glTexStorage*() 配置儲存空間
  4. glTexParameter*() 設定參數
  5. glTexSubImage*() 上傳內容
Sampler uniform 
uniform sampler2D      texture1;
uniform sampler3D      texture2;
uniform sampler1DArray texture3;

Sampler uniform 本質是 int，它的值表示用哪一個 texture image unit。

// C++：render 時把 texture 接到 unit 0，sampler 設成 0
glUseProgram(program);
glBindVertexArray(vao);
glActiveTexture(GL_TEXTURE0);                // 選 texture image unit 0
glBindTexture(GL_TEXTURE_2D, texture);       // glBindTexture 把 texture object 綁到「目前的 unit」！
GLint texture_location = glGetUniformLocation(program, "texture");
glUniform1i(texture_location, 0);            // sampler2D 的值 = unit 編號 0（不是 texture ID）
glDrawArrays(GL_TRIANGLES, 0, 3);

// 多張 texture：每張一個 unit
glActiveTexture(GL_TEXTURE0); glBindTexture(GL_TEXTURE_2D, texture1);
glActiveTexture(GL_TEXTURE1); glBindTexture(GL_TEXTURE_2D, texture2);
glUniform1i(glGetUniformLocation(program, "texture1"), 0);
glUniform1i(glGetUniformLocation(program, "texture2"), 1);

建立與初始化 texture

// C++：講義的 Simple Texture
GLuint texture;
glGenTextures(1, &texture);
glBindTexture(GL_TEXTURE_2D, texture);
glTexStorage2D(GL_TEXTURE_2D,   // 2D texture
               1,               // 1 mipmap level
               GL_RGBA32F,      // 32-bit floating-point RGBA
               256, 256);       // 256 × 256 texels

float* data = new float[256 * 256 * 4];
generate_texture(data, 256, 256);
glTexSubImage2D(GL_TEXTURE_2D,
                0,              // level 0
                0, 0,           // offset 0, 0
                256, 256,       // 換掉整張
                GL_RGBA,        // 4 個 channel
                GL_FLOAT,       // 浮點資料
                data);
delete[] data;                  // OpenGL 已經有自己的副本

void generate_texture(float* data, int width, int height) {
    for (int y = 0; y < height; y++)
        for (int x = 0; x < width; x++) {
            data[(y * width + x) * 4 + 0] = (float)((x & y) & 0xFF) / 255.0f;
            data[(y * width + x) * 4 + 1] = (float)((x | y) & 0xFF) / 255.0f;
            data[(y * width + x) * 4 + 2] = (float)((x ^ y) & 0xFF) / 255.0f;
            data[(y * width + x) * 4 + 3] = 1.0f;
        }
}

generate_texture 產生的 256×256 影像（R = x AND y、G = x OR y、B = x XOR y）

Texture 操作：filtering、mipmap、wrapping、comparison

GPU 有專用硬體做這些 texture 操作；尤其 filtering 對畫質非常重要。這也是 texture 和 buffer 的主要差別：texture 可以被過濾，buffer 不行。

Filtering 的目標

算出一個 fragment 蓋到的所有 texel 的總貢獻。把 fragment 想成房間的一扇窗，你只能用一個顏色描述窗外的景色——理論上最好的答案是所有射入光線的平均色。

正確算平均要用 Monte Carlo 等方法 → 即時渲染太貴。OpenGL 提供簡化、硬體加速的版本：nearest、bilinear、mipmapping、anisotropic。

Magnification vs Minification
  • 放大（一個 texel 蓋好幾個 fragment）：要內插顏色，避免一格一格的方塊感
  • 縮小（一個 fragment 蓋好幾個 texel）：希望一次讀取就拿到所有 texel 的平均 → mipmap
方法做法品質 / 速度
Nearest取最近的 texel最便宜、最差（Minecraft 故意用）
Bilinear2×2 鄰近 texel 內插較慢、較好
Anisotropic依相機投影的形狀取更多樣本可能很慢、最好；看硬體是否支援

互動：隧道地板（同一張貼圖、四種過濾）

講義的 Tunnel 範例：遠處的 texel 比像素小很多（縮小），nearest / bilinear 會產生閃爍的雜訊（aliasing）；mipmap 讀預先縮小的版本，遠處變平滑。

Mipmapping

  • 每一層是上一層 2×2 預先平均的結果，從原尺寸一路到 1×1
  • 縮小時從較小的層取樣：在 level 1 讀 1 個 texel = 在 level 0 讀 4 個
  • 相鄰兩層的結果還可以再內插 → 層與層之間平滑過渡（GL_LINEAR_MIPMAP_LINEAR = trilinear）
  • 所有層總共只多用約 1/3 的記憶體
  • 層數在 glTexStorage2D 的 levels 參數指定；每層可以用 glTexSubImage2D(level, …) 自己上傳，或上傳 level 0 後呼叫 glGenerateMipmap() 自動產生

Wrapping：UV 超出 [0, 1] 時

設定 GL_TEXTURE_WRAP_S 和 GL_TEXTURE_WRAP_T（S、T 就是 U、V）。示意 UV 範圍 [−1, 2]，中間框是 [0, 1]。

GL_CLAMP_TO_BORDER 用 GL_TEXTURE_BORDER_COLOR 設定的顏色（這裡是黑色）。

Texture comparison

取值前先做一次比較：通過回傳 1.0、失敗回傳 0.0，再和 filter 結合後回傳。設定 GL_TEXTURE_COMPARE_MODE、GL_TEXTURE_COMPARE_FUNC。用來加速 shadow mapping。

// C++：用 texture parameter 設定這些操作
glBindTexture(GL_TEXTURE_2D, texture);
// (1) nearest-neighbor filtering
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MAG_FILTER, GL_NEAREST);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MIN_FILTER, GL_NEAREST);
// (2) bilinear filtering
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MAG_FILTER, GL_LINEAR);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MIN_FILTER, GL_LINEAR);
// (3) bilinear filtering with mipmapping
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MAG_FILTER, GL_LINEAR);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MIN_FILTER, GL_LINEAR_MIPMAP_LINEAR);
glGenerateMipmap(GL_TEXTURE_2D);
// wrapping
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_WRAP_S, GL_REPEAT);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_WRAP_T, GL_REPEAT);
常見黑畫面原因：GL_TEXTURE_MIN_FILTER 的預設值是 GL_NEAREST_MIPMAP_LINEAR（需要 mipmap）。沒產生 mipmap 又沒改 filter → texture incomplete → 取樣得到黑色。

參數完整說明：glTexParameter、Sampler Object。

Array texture（範例：Alien Rain）

  • 一個 texture object 裡放很多層貼圖
  • 除了 3D texture，每種 texture 都有 array 版（GL_TEXTURE_2D_ARRAY 等）
  • 可以自訂 texture 資料結構；同時用很多張貼圖時減少 bind 次數
  • 2D array 用 glTexStorage3D / glTexSubImage3D 指定（第三維 = 第幾層）
  • Shader 用 sampler2DArray，texture(tex, vec3(uv, layer))

Alien Rain：256 個外星人往下掉，64 種外星人貼圖放在一個 array texture；每個外星人的位置與旋轉放在 UBO。

// C++：初始化
glGenBuffers(1, &rain_buffer);                       // UBO：256 個 vec4
glBindBuffer(GL_UNIFORM_BUFFER, rain_buffer);
glBufferData(GL_UNIFORM_BUFFER, 256 * sizeof(glm::vec4), NULL, GL_DYNAMIC_DRAW);

glGenTextures(1, &tex_alien_array);
glBindTexture(GL_TEXTURE_2D_ARRAY, tex_alien_array);
glTexStorage3D(GL_TEXTURE_2D_ARRAY, 8, GL_RGBA8, 256, 256, 64);   // depth = 64 層
for (int i = 0; i < 64; i++)
    glTexSubImage3D(GL_TEXTURE_2D_ARRAY, 0, 0, 0, i,   // z offset = 第 i 層
                    256, 256, 1, GL_RGBA, GL_UNSIGNED_BYTE, image_data[i]);

// C++：render
glBindBufferBase(GL_UNIFORM_BUFFER, 0, rain_buffer);
glm::vec4* droplet = (glm::vec4*)glMapBufferRange(GL_UNIFORM_BUFFER, 0,
    256 * sizeof(glm::vec4), GL_MAP_WRITE_BIT | GL_MAP_INVALIDATE_BUFFER_BIT);
for (int i = 0; i < 256; i++) {
    droplet[i][0] = droplet_x_offset[i];
    droplet[i][1] = 2.0f - fmodf((t + float(i)) * droplet_fall_speed[i], 4.31f);
    droplet[i][2] = t * droplet_rot_speed[i];
    droplet[i][3] = 0.0f;
}
glUnmapBuffer(GL_UNIFORM_BUFFER);
for (int alien_index = 0; alien_index < 256; alien_index++) {
    glVertexAttribI1i(0, alien_index);       // 整數 attribute 常數
    glDrawArrays(GL_TRIANGLE_STRIP, 0, 4);   // 一個四邊形
}
// GLSL：Vertex Shader
#version 410 core
layout (location = 0) in int alien_index;
out VS_OUT { flat int alien; vec2 tc; } vs_out;
struct droplet_t { float x_offset; float y_offset; float orientation; float unused; };
layout(std140) uniform droplets { droplet_t droplet[256]; };
void main(void)
{
    const vec2[4] position = vec2[4](vec2(-0.5, -0.5), vec2(0.5, -0.5),
                                     vec2(-0.5,  0.5), vec2(0.5,  0.5));
    vs_out.tc = position[gl_VertexID].xy + vec2(0.5);
    float co = cos(droplet[alien_index].orientation);
    float so = sin(droplet[alien_index].orientation);
    mat2 rot = mat2(vec2(co, so), vec2(-so, co));
    vec2 pos = 0.25 * rot * position[gl_VertexID];
    gl_Position = vec4(pos.x + droplet[alien_index].x_offset,
                       pos.y + droplet[alien_index].y_offset, 0.5, 1.0);
    vs_out.alien = alien_index % 64;   // 第幾層貼圖
}
// GLSL：Fragment Shader
#version 410 core
layout (location = 0) out vec4 color;
uniform sampler2DArray tex_aliens;
in VS_OUT { flat int alien; vec2 tc; } fs_in;
void main(void)
{
    color = texture(tex_aliens, vec3(fs_in.tc, float(fs_in.alien)));
}
flat qualifier

一般情況頂點和 fragment 不是 1:1，每個頂點的資料會在 primitive 上插值給每個 fragment。加上 flat 就不插值：這個 primitive 產生的所有 fragment 都拿到同一個值。整數（如 layer index）不能插值，所以必須 flat。
