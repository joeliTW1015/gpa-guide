講義 01 · Transformation

座標轉換（Transformation）

在進入 OpenGL 之前要先會的數學：向量、齊次座標、4×4 矩陣，以及把一個點從「模型檔裡的座標」一路變成「螢幕上的像素」所經過的六個座標空間。

本章重點
  • 渲染就像拍照：Model（擺道具）→ View（架相機）→ Projection（選鏡頭）→ Viewport（沖洗成照片）。
  • 點用 (x, y, z, 1)、方向用 (x, y, z, 0)；所有轉換都是 4×4 矩陣左乘在 column vector 上，最右邊的矩陣最先作用。
  • 一個 4×4 矩陣的四個 column = 新座標系的 X 軸、Y 軸、Z 軸、原點 → 「轉換」就是「換座標系」。
  • 六個空間：Object →(M)→ World →(V)→ Eye →(P)→ Clip →(÷w)→ NDC →(Viewport)→ Screen。前三步你自己做（C++ / vertex shader），後兩步 OpenGL 自動做。
  • 前三個空間是右手座標系，Projection 之後變成左手座標系（相機看向 −z → NDC 的 +z 往裡面）。

向量（Vector）

向量的兩種意義
  • 點：空間中的一個位置 (x, y, z)
  • 方向：從原點指向該點的箭頭
長度（2-norm / Euclidean norm）
|V| = √(V.x² + V.y² + V.z²)

長度為 1 的向量叫 unit vector 或 normalized vector：normalize(V) = V / |V|。

內積 Dot product
dot(A, B) = |A| |B| cos θ = A.x·B.x + A.y·B.y + A.z·B.z
  • 幾何意義：A 投影到 B 方向的長度 × |B|
  • dot(A,B) = dot(B,A)；cos θ = cos(2π − θ)，所以角度方向不影響結果
  • = 0 垂直、> 0 夾角 < 90°、< 0 夾角 > 90°
  • 用途：算夾角、判斷前後、光照 max(dot(N, L), 0)
外積 Cross product（只在 3D 討論；2D 看成 z = 0 的 3D 向量）
cross(A, B) = |A| |B| sin θ · n
cross(A, B) =A.y·B.z − A.z·B.yA.z·B.x − A.x·B.zA.x·B.y − A.y·B.x
  • 結果垂直於 A 和 B，方向由右手定則決定：右手四指從 A 彎向 B，大拇指就是 A×B。
  • cross(A, B) = −cross(B, A)（順序反過來方向相反）
  • 長度 = A、B 張成的平行四邊形面積
  • 用途：三角形法向量 normalize(cross(B−A, C−A))、lookAt 算相機的右方向

互動：dot 與 cross

A 角度 長度
B 角度 長度

紅線是 A 投影到 B 方向的部分。cross 在 2D 只有 z 分量：正 = 指出螢幕（A→B 逆時針）、負 = 指入螢幕。

齊次座標（Homogeneous Coordinates）

用 4D 向量表示 3D
  • 點：(x, y, z, 1)　方向：(x, y, z, 0)
  • 每個頂點是一個 column vector，w 對點不為 0、對方向為 0
  • 所有運算都是矩陣乘法
  • 點 − 點 = 方向（w：1 − 1 = 0）；點 + 方向 = 點

數學上沒有非用不可的理由，但好處很多：平移也能寫成矩陣乘法（3×3 矩陣做不到）、投影幾何（perspective）也能統一用矩陣處理。

例：同一個平移矩陣作用在點與方向

點被移動了、方向沒變——法向量、光線方向本來就不該因物體平移而改變，w = 0 自動做對。

矩陣 = 一個座標系

矩陣可以看成「一排 column vector」。在圖學裡我們關心的是矩陣乘上向量之後的效果，稱為 matrix transformation。一個 4×4 矩陣其實描述了一個座標系：

XxYxZxOxXyYyZyOyXzYzZzOz0001 ← 前三個 column：新座標系的 X 軸、Y 軸、Z 軸方向；第四個 column：新座標系的原點

把「在座標系 A 中表示的點」乘上「A 在 B 中的軸與原點」，就得到「同一個點在 B 中的座標」。這就是 change of basis（換基底）。

互動：同一個點、兩個座標系

A 的原點在 B 中 x y
A 相對 B 旋轉 °
P 在 A 中 x y

預設值就是講義的例子：A 的原點在 B 的 (3, 3)、A 的 X 軸 = (0.8, −0.6)，P 在 A 中是 (1, 1) → 在 B 中是 (4.4, 3.2)。

OpenGL 的矩陣慣例

  • 頂點用 4×4 矩陣轉換
  • 所有轉換都是矩陣相乘
  • 矩陣一律左乘（pre-multiply）：p' = M p
  • 記憶體以 column-major 存放：GLfloat M[16] 的前 4 個數是第 1 個 column
  • GLM 也是 column-major，所以 glUniformMatrix4fv(loc, 1, GL_FALSE, glm::value_ptr(M)) 的 transpose 填 GL_FALSE

平移量在 m12、m13、m14。GLM 的寫法 M[col][row]：M[3][0] 就是 x 方向平移。

旋轉：從 2D 推導

x′ = r cos(φ + θ) = r cos φ cos θ − r sin φ sin θ = x cos θ − y sin θ
y′ = r sin(φ + θ) = r sin φ cos θ + r cos φ sin θ = x sin θ + y cos θ

3D 旋轉：Euler 角與 Quaternion

方法做法優點缺點
繞 x / y / z 軸上面三個矩陣之一最簡單只能繞座標軸
Euler angles (θx, θy, θz)依序乘上三個軸的旋轉矩陣直觀（pitch / yaw / roll）結果依乘法順序而不同；有 gimbal lock

Gimbal lock（萬向鎖）

Euler 角依序繞三個軸轉。當中間那次旋轉剛好 ±90°（例如 pitch = 90°），第一個軸和第三個軸會轉到同一條線上，此時改 yaw 和改 roll 效果一樣 → 少了一個自由度，某些方向轉不過去。

View 矩陣：架好相機

View 矩陣設定相機在 world space 的位置與方向，需要三個參數：

  • E（Eye）：相機位置
  • C（Center）：看向的點
  • U（Up）：大概的上方向

要「飛越」3D 世界：每幀改 view 矩陣再重畫。

移動相機 = 反方向移動世界

相機往 +z 走 1 步，和整個世界往 −z 走 1 步，拍出來的照片完全一樣。所以 OpenGL 裡沒有「相機物件」，view 矩陣其實是在移動整個世界，讓相機待在原點、看向 −z。

Mview = Mrotation · Mtranslation：

  1. 先平移 −E，把相機搬到原點
  2. 再旋轉，讓相機的前方對齊 −z 軸、上方對齊 +y 軸
算出相機的三個軸
  • F = normalize(C − E)　前方
  • S = normalize(cross(F, U))　右方
  • U′ = normalize(cross(S, F))　真正的上方（和 F、S 都垂直）

(S, U′, F) 其實是左手座標系，所以 F 那一列要加負號換回右手，順便讓前方對到 −z。

Mview =SxSySz0U′xU′yU′z0−Fx−Fy−Fz00001·100−Ex010−Ey001−Ez0001

這就是 glm::lookAt(E, C, U)。旋轉部分的 row 是相機三軸（因為是「世界 → 相機」的反向轉換，旋轉矩陣的逆 = 轉置）。

Projection 矩陣：選鏡頭

Projection 把 3D 場景投影到 2D 平面（像相機鏡頭），同時在 OpenGL 中把右手座標系（RHC）轉成左手座標系（LHC）。分成正交與透視兩種。

Orthographic：M = Mscaling · Mtranslation
  1. 把 view volume（left, right, bottom, top, near, far）的中心移到原點
  2. 再縮放成 [−1, 1]³ 的立方體（clip space）
  3. 別忘了 RHC → LHC：z 乘 −1

Center = ((r,t,f) + (l,b,n)) / 2
Size = (r,t,f) − Center

2/(r−l)00−(r+l)/(r−l)02/(t−b)0−(t+b)/(t−b)00−2/(f−n)−(f+n)/(f−n)0001

glm::ortho(l, r, b, t, n, f)。紅色的負號就是左右手轉換。

Perspective：由 frustum 六個參數定義

left, right, bottom, top 是 near 平面上的範圍：

2n/(r−l)0(r+l)/(r−l)002n/(t−b)(t+b)/(t−b)000−(f+n)/(f−n)−2fn/(f−n)00−10

最後一列 (0, 0, −1, 0) 讓 w = −zeye（= 到相機的距離）。之後除以 w → 越遠的點 x、y 越小 → 近大遠小。

glm::perspective(fovy, aspect, near, far) 是對稱 frustum（l = −r、b = −t）的簡便寫法。

逆矩陣、串接與順序

逆矩陣的捷徑

一般方法：高斯消去、LU 分解。但基本轉換可以直接看出來：

  • T⁻¹(Tx,Ty,Tz) = T(−Tx,−Ty,−Tz)
  • R⁻¹(R, θ) = R(R, −θ) = Rᵀ(R, θ)
  • S⁻¹(Sx,Sy,Sz) = S(1/Sx, 1/Sy, 1/Sz)

旋轉矩陣的逆 = 轉置，對任何旋轉矩陣都成立（cos(−θ) = cos θ、sin(−θ) = −sin θ）。

矩陣串接（Concatenation）

平移、旋轉、縮放相乘可以組成任意 affine 轉換。

同一個轉換要套在很多頂點上 → 先算好 M = A·B·C·D（一次）再算 p′ = M p（每個頂點一次），比每個頂點乘四次便宜很多。

困難的地方在於：怎麼從需求組出正確的轉換。

順序：最右邊的先作用
p′ = A B C p = A ( B ( C p ) )

C 最先作用、A 最後。所以 T · R · S = 先縮放、再旋轉、最後平移。

有些書用 row vector：p′ᵀ = pᵀ Cᵀ Bᵀ Aᵀ，順序是反的。看別人的程式碼時要注意慣例。

數字驗證順序

點 p = (1, 0, 0)，R = 繞 y 軸 90°，T = 往 +x 移 5：

  • T · R · p：先轉 → (0, 0, −1) → 再平移 → (5, 0, −1)（原地轉完再搬過去）
  • R · T · p：先平移 → (6, 0, 0) → 再繞原點轉 → (0, 0, −6)（被甩到很遠，像繞太陽公轉）

教室比喻

每個物體都有自己的 object space（老師、學生各自以自己為原點）。把它們放進同一個 world space（教室），就是用矩陣做座標轉換。

為什麼要分這麼多空間？OpenGL 最終只是在螢幕上畫像素。要表達「我想畫一個三角形」，把過程拆成一連串座標空間轉換（divide-and-conquer），對人比較好理解、也比較好擴充。

座標空間左 / 右手說明下一步
Object space（model space）右手模型檔的原始座標，相對於模型自己的原點。若模型是左手座標要先轉換。× Model matrix
World space右手所有物體放在同一個空間；相機通常也定義在這裡。物體之間的關係常用樹狀的 scene graph 表示（作業 1 的機器人階層就是）。× View matrix
Eye space（camera / view space）右手相機在原點、看向 −z；看得到的東西都在 −z 方向。× Projection matrix
Clip space左手view volume 中心移到原點。vertex shader 輸出的 gl_Position 就是這個空間。形狀沒變，變的是周圍的座標系。÷ w（perspective division）
NDC（normalized device space）左手可見的東西都在 [−1, 1]³ 立方體內；near 平面 z = −1、far 平面 z = +1。Viewport transformation
Screen space左手實際的像素位置 + 深度值。x, y 在 glViewport(x, y, w, h) 的矩形內；深度在 [nearVal, farVal]。—
Clip → NDC：perspective division
(x, y, z, w) → (x/w, y/w, z/w, 1)

OpenGL 自動且強制做這一步，無法關閉。w = 0 時視為 (∞, ∞, ∞, 0)，在可見範圍外。

NDC → Screen：viewport transformation

由兩個 API 決定：glViewport(x, y, w, h) 對應 x、y；glDepthRange(nearVal, farVal) 對應 z（預設 0 ~ 1）。

xscreen = x + (xndc + 1) / 2 · w
yscreen = y + (yndc + 1) / 2 · h
zscreen = nearVal + (zndc + 1) / 2 · (farVal − nearVal)

MVP：程式怎麼寫

所有空間轉換最後濃縮成一行：V′ = Projection · Viewing · Modeling · V。

// main.cpp（C++，CPU）
glm::mat4 model = ...;    // 物體擺放
glm::mat4 view  = glm::lookAt(eye, center, up);
glm::mat4 proj  = glm::perspective(glm::radians(45.0f), aspect, 0.1f, 100.0f);
glm::mat4 mvp = proj * view * model;     // 順序：P · V · M
glUniformMatrix4fv(0, 1, GL_FALSE, &mvp[0][0]);   // location 0、1 個矩陣、不轉置
// vert.glsl（GLSL，GPU，每個頂點跑一次）
#version 410 core
uniform mat4 um4mvp;
in vec4 vertex;
void main()
{
    gl_Position = um4mvp * vertex;   // 輸出 clip space
}
// 之後 ÷w 與 viewport 由 OpenGL 自動完成

同一個點若離相機更遠，w 會更大 → 除完 x、y 更接近 0 → 更靠近畫面中心、看起來更小。這就是「近大遠小」。

你可能會問…（講義 Q&A）

Q1：為什麼 eye space 要把物體放在 −z？用 +z 不行嗎？

右手系的 −z 就是左手系的 +z。可見物體在左手系裡永遠在 +z。用右手系表示 model / world / eye space、左手系表示 clip / NDC / screen space 只是一種慣例，你不一定要照著做。

Q2：網路上找到的程式和講義不一樣！View 和 Projection 矩陣不同，誰才對？

有些人（例如 DirectX）所有座標都用左手系，把可見物體放在 +z，投影矩陣裡不做 RHC / LHC 轉換。只要最後座標系變成左手系，結果都一樣。所以看別人的矩陣公式時，先確認他的慣例。

Q3：最後可見的 z 值本來就在 [0, 1]，為什麼 NDC 的 z 要用 [−1, 1]？

NDC 是「每個分量都在 [−1, 1]」的正規化表示。如果 z 用 [0, 1]，NDC 會變成長方體，比較複雜。z 最後再由 glDepthRange（預設 0 ~ 1）對應到 depth buffer 的範圍。
