總覽：Fragment 的位置

綠 = programmable、橘 = optional programmable、灰 = fixed function。本講聚焦右邊三格：Fragment Shader → Per-Sample Processing → Framebuffer。完整 pipeline 見 Rendering Pipeline。

Fragment Shader Stage

特性
  • 最後一個 programmable stage
  • rasterizer 產生的每個 fragment 執行一次
  • 看不到旁邊的 fragment，彼此平行執行
做什麼
  • 決定像素的顏色
  • 執行頻率遠高於前面的 stage（1080p ≈ 200 萬像素，頂點可能才幾千個）
  • 大部分「細節」在這裡加：光照計算、貼圖取樣
範例：最簡單的 fragment shader（講義 Spinning Cube） 
// GLSL：vertex shader 用 interface block 傳顏色
#version 410 core
in vec4 position;
out VS_OUT { vec4 color; } vs_out;
uniform mat4 mv_matrix;
uniform mat4 proj_matrix;
void main(void) {
    gl_Position = proj_matrix * mv_matrix * position;
    vs_out.color = position * 2.0 + vec4(0.5, 0.5, 0.5, 0.0);   // 用位置當顏色
}

// GLSL：fragment shader，block 名稱要相同（VS_OUT），變數名可不同（vs_out / fs_in）
#version 410 core
in VS_OUT { vec4 color; } fs_in;
out vec4 color;                    // 輸出到 framebuffer 的 color attachment 0
void main(void) {
    color = fs_in.color;           // 已被 rasterizer 內插過
}

Per-Sample Processing

fragment 寫入 framebuffer 前的最後一關（fixed function），做三種測試：

全部通過才寫入 framebuffer；有開 blending 就先和 framebuffer 既有顏色混合再寫入。Depth test 的互動示範見 Rendering Pipeline。

Blending

Opacity 與 Transparency

表面光線alpha（opacity）
Opaque（不透明）完全不透光a = 1
Transparent（全透明）全部透過a = 0
Translucent（半透明）部分透過translucency = 1 − a

物理上正確的半透明很難：光和物質的內部交互複雜，而且 pipeline renderer 一次只處理一個 fragment。所以 OpenGL 用簡化的「寫入模型」。

寫入模型（Writing Model）

RGBA 的 A 存 opacity。source 顏色 b = (br, bg, bb, ba)、destination 顏色 c = (cr, cg, cb, ca)，每個分量各自乘上 factor 再相加（⊙ = 逐分量相乘）：

c′ = b ⊙ s + c ⊙ d = (br·sr + cr·dr, bg·sg + cg·dg, bb·sb + cb·db, ba·sa + ca·da)

// C++：要先開 blending，再選 factor
glEnable(GL_BLEND);
glBlendFunc(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA);   // (sfactor, dfactor)

透明物件的順序（Object Ordering）

畫半透明物件最重要的是順序：depth test 開著時，先畫近的半透明物件會把深度寫進去，後畫的遠物件被 depth test 丟掉 → 透明物體「後面」的東西消失。

處理透明物件的步驟
  1. 先畫所有不透明物件
  2. 把透明物件依深度排序（離相機遠的先）
  3. 依排序結果由遠到近畫透明物件

互相穿插的兩片（A 一部分在 B 前、一部分在 B 後）沒有正確的整體順序 → rasterization renderer 處理透明度先天困難。

Order Independent Transparency（OIT）：記錄所有 fragment → 每個像素自己排序後再混合；做法之一是在 GPU 上為每個像素建 linked list（參考：Order Independent Transparency in OpenGL 4.x）。

Off-Screen Rendering

  • OpenGL 允許你建立自己的 framebuffer，直接畫進 texture。
  • 這些 texture 可以再拿去畫別的東西或做後製。
  • 現代即時渲染極重要的技術，期末專題會用到。

為什麼 FBO 有幫助

Framebuffer Object（FBO）結構

  • FBO 定義 pipeline 的輸出區域，是一組 image 的集合，這些 image 叫 attachment：
    • Color attachment：顏色（RGB）輸出
    • Depth attachment：depth test 用的深度
    • Stencil 等
  • 建立視窗時 OS 會給一個預設 framebuffer，ID = 0（就是螢幕）；自己建的 FBO 從 ID 1 開始。
  • Texture vs Renderbuffer：要「之後拿來取樣」的（例如畫完要貼到螢幕）用 texture；只是讓 depth test 能運作、不需要讀的用 renderbuffer（RBO）。
FBO 不是 buffer object！VBO（vertex buffer object）、UBO（uniform buffer object）是存資料的 buffer；FBO 是 OpenGL object，只記錄「attachment 接到哪些 image」，本身不存像素。

Attachment 種類

Attachment接上的 image
GL_COLOR_ATTACHMENTiColor image（i = 0, 1, 2…，最多 GL_MAX_COLOR_ATTACHMENTS）
GL_DEPTH_ATTACHMENTDepth buffer
GL_STENCIL_ATTACHMENTStencil buffer
GL_DEPTH_STENCIL_ATTACHMENTDepth 和 Stencil 合在一起

使用流程（和其他 OpenGL object 一樣）

  1. glGenFramebuffers 建立 FBO
  2. glBindFramebuffer 綁定
  3. 用 glFramebufferTexture2D / glFramebufferRenderbuffer 等設定 attachment
  4. 要畫的時候再 glBindFramebuffer 把它接到 pipeline 輸出
  5. 發出 draw call → 結果寫進 FBO 的 attachment

完整的 FBO 建立程式（講義 Set Up FBO） 
// C++
GLuint fbo, depthrbo, fboDataTexture;

glGenFramebuffers(1, &fbo);                       // 1. 建 FBO

glGenRenderbuffers(1, &depthrbo);                 // 2. 建 depth renderbuffer
glBindRenderbuffer(GL_RENDERBUFFER, depthrbo);
glRenderbufferStorage(GL_RENDERBUFFER, GL_DEPTH_COMPONENT32, window_width, window_height);

glGenTextures(1, &fboDataTexture);                // 3. 建 color texture（data = NULL：只配置空間）
glBindTexture(GL_TEXTURE_2D, fboDataTexture);
glTexImage2D(GL_TEXTURE_2D, 0, GL_RGBA, window_width, window_height, 0, GL_RGBA, GL_UNSIGNED_BYTE, NULL);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_WRAP_S, GL_CLAMP_TO_EDGE);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_WRAP_T, GL_CLAMP_TO_EDGE);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MIN_FILTER, GL_LINEAR);
glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MAG_FILTER, GL_LINEAR);

glBindFramebuffer(GL_DRAW_FRAMEBUFFER, fbo);      // 4. 接上 attachment
glFramebufferRenderbuffer(GL_DRAW_FRAMEBUFFER, GL_DEPTH_ATTACHMENT, GL_RENDERBUFFER, depthrbo);
glFramebufferTexture2D(GL_FRAMEBUFFER, GL_COLOR_ATTACHMENT0, GL_TEXTURE_2D, fboDataTexture, 0);

// 建議（講義沒寫）：檢查 FBO 是否完整
if (glCheckFramebufferStatus(GL_FRAMEBUFFER) != GL_FRAMEBUFFER_COMPLETE)
    printf("FBO incomplete\n");

視窗 resize 時，texture 和 renderbuffer 的大小要重新配置（再呼叫一次 glTexImage2D / glRenderbufferStorage），否則 FBO 解析度不會跟著變。

Multiple Render Targets（MRT）

一個 FBO 可以接多個 color attachment，一個 fragment shader 同時寫進多張 texture。

// C++：建 FBO + 3 張 texture
static const GLenum draw_buffers[] = {
    GL_COLOR_ATTACHMENT0, GL_COLOR_ATTACHMENT1, GL_COLOR_ATTACHMENT2 };
glGenFramebuffers(1, &fbo);
glBindFramebuffer(GL_FRAMEBUFFER, fbo);
glGenTextures(3, &color_texture[0]);
for (int i = 0; i < 3; i++) {
    glBindTexture(GL_TEXTURE_2D, color_texture[i]);
    glTexStorage2D(GL_TEXTURE_2D, 9, GL_RGBA8, window_width, window_height);
    glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MIN_FILTER, GL_LINEAR);
    glTexParameteri(GL_TEXTURE_2D, GL_TEXTURE_MAG_FILTER, GL_LINEAR);
    glFramebufferTexture(GL_FRAMEBUFFER, draw_buffers[i], color_texture[i], 0);
}
glDrawBuffers(3, draw_buffers);   // 輸出 location i → draw_buffers[i]
// GLSL：一次寫三個輸出
#version 410 core
uniform sampler2D tex;
layout (location = 0) out vec4 color_tex;     // → ATTACHMENT0
layout (location = 1) out vec4 color_normal;  // → ATTACHMENT1
layout (location = 2) out vec4 color_depth;   // → ATTACHMENT2
in VS_OUT { vec2 texcoord; vec3 normal; } fs_in;
void main(void) {
    color_tex    = texture(tex, fs_in.texcoord).rgba;
    color_normal = vec4(fs_in.normal, 1.0);
    color_depth  = vec4(vec3(gl_FragCoord.z), 1.0);
}

glDrawBuffers：location ≥ n 的輸出會被設為 GL_NONE，寫的值直接丟棄。glTexStorage2D 是 4.2+（macOS 4.1 改用 glTexImage2D）。

影像後製（Image Post-Processing using FBO）

流程：先把場景畫進 FBO texture → 再畫一個全螢幕四邊形，fragment shader 讀 texture 做處理 → 輸出到螢幕。每個像素在 GPU 上平行處理（對照 CPU 版需要兩層 for 迴圈逐像素跑）。

下面用 JavaScript 在瀏覽器裡模擬同一份 shader 邏輯（每個像素跑一次 main）。調參數看效果，右邊是對應的 GLSL。

左：原圖（FBO texture）　右：後製結果

smoothstep

edge0 edge1 
genType smoothstep(genType edge0, genType edge1, genType x);
  • edge0 / edge1：Hermite 曲線的下 / 上邊界
  • x：輸入值
  • x ≤ edge0 → 0；x ≥ edge1 → 1；中間平滑過渡（兩端斜率為 0）
// 等價於
genType t = clamp((x - edge0) / (edge1 - edge0), 0.0, 1.0);
return t * t * (3.0 - 2.0 * t);

藍 = smoothstep、灰虛線 = 線性 clamp。DoG 用它把邊緣值平滑地映射到黑白；星空範例用它讓小星星淡出。

Point Sprites

  • 想畫很多帶貼圖的點做粒子效果。不用 point sprite 就得畫大量帶貼圖的四邊形。
  • OpenGL 為 point 模式提供自動產生 texture coordinate 的機制 = Point Sprites。
使用步驟
  1. 啟用 GL_POINT_SPRITE（以及 GL_PROGRAM_POINT_SIZE 讓 shader 設定大小）
  2. 用 GL_POINTS 模式畫
  3. fragment shader 從內建變數 gl_PointCoord（點內的 (0,0)~(1,1)）讀 texture coordinate

Core profile（3.2+）中 point sprite 永遠開著，glEnable(GL_POINT_SPRITE) 在 core profile 會產生 GL_INVALID_ENUM，可省略。

速度

Flying Star Field 示意：每顆星 z 隨時間增加（fract 循環），越近越大（gl_PointSize = 20·z²）、用 smoothstep(1, 7, size) 淡入，加法混合（GL_ONE, GL_ONE）。

Flying Star Field 程式（講義） 
// GLSL：Vertex Shader
#version 410 core
layout (location = 0) in vec3 position;   // camera space
layout (location = 1) in vec3 color;
uniform float time;
uniform mat4 proj_matrix;
flat out vec4 starColor;
void main(void) {
    vec4 starPosition = vec4(position.xy, position.z + time, 1.0);
    float starSize = 20.0 * starPosition.z * starPosition.z;
    starColor = vec4(color * smoothstep(1.0, 7.0, starSize), 1.0);
    starPosition.z = (999.9 * starPosition.z) - 1000.0;
    gl_Position = proj_matrix * starPosition;
    gl_PointSize = starSize;
}
// GLSL：Fragment Shader
#version 410 core
layout (location = 0) out vec4 color;
uniform sampler2D tex_star;
flat in vec4 starColor;
void main(void) {
    color = starColor * texture(tex_star, gl_PointCoord);
}
