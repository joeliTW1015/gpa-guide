Demo 練習題

為什麼 L2 Arm 的矩陣要乘上 Mtorso 和 Marm1？

L2 Arm 的 local 矩陣只描述「相對於 L1 Arm 的手肘」的位置與旋轉。往左乘 Marm1 轉到 torso 空間，再乘 Mtorso 轉到 world。所以 torso 移動 / 旋轉時整條手臂跟著動。

畫部位時的 scale 為什麼不能傳給子節點？

scale 只是把單位大小的 Cube / Capsule 拉成部位的形狀。若傳下去，子節點的平移量和形狀都會被父的 scale 拉伸（例如手臂被拉長兩倍，手肘的位置也被拉遠兩倍、前臂也變形）。做法：Mjoint 往下傳，畫自己時另外乘 scale。在 5. 勾「錯誤：scale 傳給子節點」可以看到效果。

T * R 和 R * T 差在哪？手臂要繞肩膀轉該用哪個？

套在頂點上是由右往左：T * R * v = 先在原點旋轉，再平移到關節 → 繞關節轉。R * T * v = 先平移出去再繞「父的原點」轉 → 手臂繞 torso 中心公轉。繞肩膀轉：M = T(肩膀位置) * R(角度)，畫的時候再 * T(0,-半長,0) * S(...) 讓 mesh 往下長。

glm::rotate 的角度單位？

弧度（radian）。用角度要 glm::radians(30.0f)。

VAO 存了什麼？為什麼每個 mesh 一個 VAO？

VAO 記錄 attribute 設定（哪個 location 從哪個 VBO、什麼格式、stride、offset 讀）以及 element buffer 綁定。每個 mesh 一個 VAO，畫的時候 glBindVertexArray 一行就切換全部設定。

uniform 和 vertex attribute 差在哪？

attribute 每個頂點不同（position、uv），從 VBO 讀；uniform 在一次 draw call 內所有頂點相同（M、V、P、顏色、sampler），用 glUniform* 設定，要先 glUseProgram。

沒開 depth test 會怎樣？為什麼每幀要 clear depth？

沒開：後畫的永遠蓋掉先畫的，背後的腿可能畫在身體前面。不 clear depth：上一幀的深度殘留，新畫面大部分 fragment 被判定「比較遠」而丟掉 → 畫面殘缺或全空。

stbi_set_flip_vertically_on_load(true) 為什麼需要？

圖檔第一列是影像最上面，OpenGL texture 的 v=0 是最下面。不翻轉的話貼圖上下顛倒。

VS 輸出的 gl_Position 在哪個空間？之後誰做 perspective divide？

Clip space。之後 fixed function 的 primitive assembly / clipping 做除以 w 得到 NDC，再經 viewport transform 到 screen。

動畫為什麼用 glfwGetTime() 的時間差，而不是每幀 +1？

每幀 +1 的速度跟 FPS 綁在一起，換台電腦（或關掉 vsync）動畫速度就不同。用經過的時間累加，任何 FPS 下速度都一樣；暫停 = 不累加時間。

5. 階層模型互動

點左邊的節點或右邊的部位選取，拖曳滑桿轉動該關節。2D 示意，概念與 3D 相同（3D 只是 rotate 多一個軸）。

Torso 角度 0° ｜ Torso X
示範錯誤：

選取部位的 world matrix（2D 齊次 3×3）

最後一欄是關節在 world 的位置。轉父節點時，子節點的這一欄跟著變。

對應到 3D 程式

// 往下傳的是「關節矩陣」，畫自己時另外乘 offset + scale
glm::mat4 torso = glm::translate(glm::mat4(1.0f), robotPos);
torso = glm::rotate(torso, robotYaw, glm::vec3(0, 1, 0));
drawPart(cube, glm::scale(torso, glm::vec3(1.0f, 1.4f, 0.6f)), color);      // scale 只給自己

glm::mat4 arm1 = glm::translate(torso, glm::vec3(-0.65f, 0.6f, 0));       // 移到肩膀
arm1 = glm::rotate(arm1, angleArm1, glm::vec3(1, 0, 0));                   // 繞肩膀轉
drawPart(capsule, glm::scale(glm::translate(arm1, glm::vec3(0, -0.4f, 0)),  // 往下長半截
                             glm::vec3(0.25f, 0.4f, 0.25f)), color);       // Capsule 高 2 → 0.4 倍 = 0.8

glm::mat4 arm2 = glm::translate(arm1, glm::vec3(0, -0.8f, 0));            // 手肘：用 arm1，不是畫 arm1 的那個矩陣
arm2 = glm::rotate(arm2, angleArm2, glm::vec3(1, 0, 0));
drawPart(capsule, glm::scale(glm::translate(arm2, glm::vec3(0, -0.4f, 0)),
                             glm::vec3(0.22f, 0.4f, 0.22f)), color);

glm::translate(m, v) = m * T(v)（右乘），所以一路寫下來就是 Mtorso * Marm1 * Marm2。也可以用 std::stack<glm::mat4> 做 push / pop，概念一樣。

3. 載入 OBJ → VAO / VBO

template 附 tiny_obj_loader.h（header-only）。TINYOBJLOADER_IMPLEMENTATION 只能在一個 .cpp define 一次（本作業就是 main.cpp）。

#define TINYOBJLOADER_IMPLEMENTATION
#include "tiny_obj_loader.h"

struct Mesh { GLuint vao = 0, vbo = 0; GLsizei count = 0; };

Mesh loadObj(const char* path)
{
	tinyobj::attrib_t attrib;
	std::vector<tinyobj::shape_t> shapes;
	std::vector<tinyobj::material_t> materials;
	std::string warn, err;
	if (!tinyobj::LoadObj(&attrib, &shapes, &materials, &warn, &err, path)) {
		fprintf(stderr, "LoadObj failed: %s %s\n", path, err.c_str());
		return {};
	}
	std::vector<float> data;                       // interleaved: pos(3) uv(2)
	for (const auto& s : shapes)
		for (const auto& idx : s.mesh.indices) {      // 每個 index = 三角形的一個角
			for (int k = 0; k < 3; ++k) data.push_back(attrib.vertices[3 * idx.vertex_index + k]);
			for (int k = 0; k < 2; ++k) data.push_back(attrib.texcoords[2 * idx.texcoord_index + k]);
		}
	Mesh m;
	m.count = (GLsizei)(data.size() / 5);
	glGenVertexArrays(1, &m.vao);
	glBindVertexArray(m.vao);
	glGenBuffers(1, &m.vbo);
	glBindBuffer(GL_ARRAY_BUFFER, m.vbo);
	glBufferData(GL_ARRAY_BUFFER, data.size() * sizeof(float), data.data(), GL_STATIC_DRAW);
	GLsizei stride = 5 * sizeof(float);
	glVertexAttribPointer(0, 3, GL_FLOAT, GL_FALSE, stride, (void*)0);                     // position
	glVertexAttribPointer(1, 2, GL_FLOAT, GL_FALSE, stride, (void*)(3 * sizeof(float)));   // uv
	glEnableVertexAttribArray(0);
	glEnableVertexAttribArray(1);
	glBindVertexArray(0);
	return m;
}
  • OBJ 的 v / vt 各自有獨立 index，所以這裡把每個角展開成一筆完整頂點、用 glDrawArrays。沒做光照就不需要 normal（vn）。換成別的 OBJ 要先檢查 texcoord_index 是否 ≥ 0。
  • stride / offset 怎麼算見 Stacked vs Interleaved。
  • 實測頂點數：Cube 36、Sphere 2304、Capsule 2496。
Mesh cube, sphere, capsule, cylinder;
// main()，GLAD 初始化之後

8. 鍵盤 / 滑鼠控制位置與旋轉 
glm::vec3 robotPos(0.0f);
float robotYaw = 0.0f;
bool dragging = false;
double lastMouseX = 0.0;

// 鍵盤：每幀檢查（glfwGetKey），按住就持續移動，乘 dt 和 FPS 無關
void processInput(GLFWwindow* window, float dt)
{
	if (ImGui::GetIO().WantCaptureKeyboard) return;
	float move = 2.0f * dt, turn = 2.0f * dt;
	if (glfwGetKey(window, GLFW_KEY_W) == GLFW_PRESS) robotPos.z -= move;
	if (glfwGetKey(window, GLFW_KEY_S) == GLFW_PRESS) robotPos.z += move;
	if (glfwGetKey(window, GLFW_KEY_A) == GLFW_PRESS) robotPos.x -= move;
	if (glfwGetKey(window, GLFW_KEY_D) == GLFW_PRESS) robotPos.x += move;
	if (glfwGetKey(window, GLFW_KEY_Q) == GLFW_PRESS) robotYaw += turn;
	if (glfwGetKey(window, GLFW_KEY_E) == GLFW_PRESS) robotYaw -= turn;
}
// main loop 每幀：processInput(window, dt);

// 滑鼠：左鍵按下開始拖曳、放開結束
void mouse_button_callback(GLFWwindow* window, int button, int action, int mods)
{
	if (button != GLFW_MOUSE_BUTTON_LEFT) return;
	if (action == GLFW_RELEASE) { dragging = false; return; }
	if (ImGui::GetIO().WantCaptureMouse) return;   // 在選單上就不轉機器人
	dragging = true;
	double y;
	glfwGetCursorPos(window, &lastMouseX, &y);
}

void cursor_pos_callback(GLFWwindow* window, double x, double y)
{
	if (dragging) robotYaw += (float)(x - lastMouseX) * 0.01f;   // 左右拖曳 = 轉身
	lastMouseX = x;
}

// main()：在 ImGui_ImplGlfw_InitForOpenGL(window, true) 之前
glfwSetMouseButtonCallback(window, mouse_button_callback);
glfwSetCursorPosCallback(window, cursor_pos_callback);

Torso 的矩陣從 translate(robotPos) + rotate(robotYaw) 開始，整隻機器人就跟著動。

驗收：按住 WASD 移動、QE / 左鍵拖曳轉身；在 ImGui 視窗上拖曳不會轉到機器人；選單仍可操作。

GLuint loadTexture(const char* path)

	stbi_image_free(data);
	return tex;
}
