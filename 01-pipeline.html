OpenGL Rendering Pipeline

一個三角形從 C++ 陣列出發、經過哪些 stage、每個 stage 做什麼、能用哪些 API 設定；以及第一支 OpenGL shader 程式（OpenGL 101：畫一個點、一個三角形）。

本章重點
  • Pipeline = 一串 stage，資料流進、處理、流出。Fixed-function stage 只能用 API 調狀態；programmable stage 跑你寫的 shader。
  • 順序：Vertex Specification → Vertex Shader →（Tessellation）→（Geometry）→ Rasterizer → Fragment Shader → Per-Sample Processing → Framebuffer。
  • Vertex / Tessellation / Geometry 合稱 Vertex Processing：最後一個啟用的必須輸出 gl_Position（clip space）。
  • Rasterizer 依序做 culling → clipping → ÷w → viewport → 光柵化（並插值 VS 的輸出）→ multisampling。
  • Per-sample 做 scissor / stencil / depth test，通過後（可選）blending 再寫進 framebuffer。
  • Shader 編譯成 shader object → attach 到 program → link → glUseProgram；畫圖前必須 bind 一個 VAO（即使沒有任何輸入）。

Pipeline 與 OpenGL Object

這門課講的是 rasterization rendering pipeline。它由多個 stage 組成，依功能可以分成四大類：

OpenGL 的物件導向資源管理

GPU 記憶體以 resource object 表示：

  • Buffer Object：陣列或結構的資料（幾何、相機設定、查表…）
  • Texture Object：1D、2D、3D、cube 影像（或它們的 array）

Pipeline 設定也用 object 表示：

  • Vertex Array Object（VAO）：設定 pipeline 的輸入
  • Shader Object：某個 programmable stage 的一個 shader
  • Shader Program Object：pipeline 用到的所有 shader

細節見 講義 04 OpenGL Objects。

怎麼用這些物件
  • 每個物件用一個 GLuint（無號整數）識別
  • 用 API + 這個 ID 操作物件
  • 把物件 bind 到 pipeline 來設定它，然後發出 draw command 開始渲染

常見的渲染流程：

設定 pipeline 給 Object#1 → draw Object#1
設定 pipeline 給 Object#2 → draw Object#2
...

兩個物件共用一些設定時，連續畫就不用重設 → 少呼叫 API → 直接省 CPU。

各 stage 詳解

Vertex Specification fixed
  • 第一個 stage：從一或多個 buffer object 組出頂點，交給後面的 stage
  • 應用程式用一個 VAO 當作設定
  • 搭配不同 draw command 產生不同輸入格式
  • 設定 API：glBindVertexArray(vao)、glDraw*（draw command 也標示一次渲染的開始）

→ 詳見 講義 05

Vertex Shader programmable
  • 第一個 programmable stage，每個頂點執行一次
  • 彼此獨立、不知道 primitive 的拓樸（不知道自己屬於哪個三角形）
  • 常做：套用轉換矩陣、vertex skinning（骨架動畫）、per-vertex 光照、任何和形狀有關的計算
Tessellation Shader optional
  1. Tessellation Control Shader（programmable）
  2. Tessellation Engine（fixed function）
  3. Tessellation Evaluation Shader（programmable）

三個子 stage 要一起用。把表示平滑曲面的高階 patch 細分成一般三角形。

  • 常見誤解：tessellation ≠ triangulation
  • 為什麼需要：高解析模型（一個角色 10 萬頂點）佔大量儲存與頻寬 → 存粗模型、在 GPU 上依需要細分；同一份輸入可在不同硬體上調整細節；美術不必處理三角形細節
Geometry Shader optional
  • 最後一個能改幾何的 stage，每個 primitive 執行一次
  • 可以用程式新增 / 刪除幾何、輸出和輸入不同的 primitive 類型
  • Transform Feedback：把幾何存回 buffer object → 重複使用昂貴的 vertex / tessellation 結果，或讓 CPU 讀回（GPU 當協同處理器）
  • 因效能問題，演算法設計中較少使用
Vertex Processing = Vertex + Tessellation + Geometry shader stage，都處理頂點與幾何。最後一個啟用的 stage 必須輸出 clip space 座標 gl_Position 給 Rasterizer。只有 VS + FS 時就是 VS 負責。
Fragment Shader programmable
  • 最後一個 programmable stage，rasterizer 產生的每個 fragment 執行一次
  • 不知道相鄰的 fragment，彼此平行執行
  • 白話：決定一個像素的顏色；執行頻率遠高於前面（1080p ≈ 200 萬個像素）
  • 大部分細節在這裡加上：光照計算、貼圖

→ 詳見 講義 06

Framebuffer
  • 輸出目標：預設是視窗（back buffer）
  • 也可以是自訂的 FBO（render to texture，後製用）
  • Double buffering：畫在 back buffer，glfwSwapBuffers 後顯示

Rasterizer（fixed function）

由三個子 stage 組成：Vertex Post-Processing、Primitive Assembly、Rasterization。它們在硬體上沒有嚴格分開、順序也可能不同，所以通常直接討論它做的事（邏輯順序）：

#操作做什麼設定 API
1Face Culling丟掉朝向（或背向）相機的 primitive。封閉的物體看不到「裡面」，所以背面永遠不會出現在畫面上 → back-face culling 省一半工作glEnable(GL_CULL_FACE)、glFrontFace、glCullFace
2Primitive Culling完全在 view volume 外 → 整個丟掉（同上）
3Primitive Clipping（Frustum Clipping）部分在 view volume 內 → 切成數個完全在內的新 primitive；在 clip space 做非常有效率glEnable(GL_CLIP_DISTANCEi)（自訂裁切平面）
4Perspective Division（Homogeneous Division）clip space → NDC（÷w）無法控制
5Viewport TransformationNDC → screen spaceglViewport、glDepthRange
6Rasterization把幾何轉成規則取樣的表示（fragment），才能寫進像素影像；VS 的 out 在這裡被插值後送進 FS 的 inglPolygonMode、GL_POLYGON_OFFSET + glPolygonOffset、glPointSize、glLineWidth
7Multisampling簡化、最佳化、硬體加速的 anti-aliasingglEnable(GL_MULTISAMPLE)

÷w 與 viewport 的數學見 講義 01 六個座標空間；光柵化演算法本身是電腦圖學（CS5500）的內容。

範例：插值（interpolation）

一條邊的兩端，頂點 A 顏色 (1,0,0) 紅、頂點 B 顏色 (0,0,1) 藍。VS 只在 A、B 兩點各跑一次，但中間有很多像素：

  • 距 A 25% 處的 fragment 拿到 0.75·紅 + 0.25·藍 = (0.75, 0, 0.25)
  • 正中間拿到 (0.5, 0, 0.5) 紫色

三角形內部則用三個頂點的 barycentric 權重（加總為 1）混合。任何從 VS out 出來的值（顏色、UV、法向量、世界座標）都會這樣被插值後送進 FS——這就是為什麼 FS 能拿到「每個像素自己的 UV」。下方 OpenGL 101 的 RGB 三角形就是這個效果。

注意：插值後的法向量長度不再是 1 → FS 裡要再 normalize 一次。

Per-Sample Processing（fixed function）

fragment 寫進 framebuffer 前的最後一個 stage。做三種測試，全部通過才寫入；若開了 blending，先混合再寫入。

操作做什麼設定 API
Scissor Test丟掉使用者指定矩形以外的 fragment，用來把輸出限制在某個區域glEnable(GL_SCISSOR_TEST)、glScissor
Stencil Test拿 fragment 的參考值和 stencil buffer 的內容比較；stencil buffer 也可以動態更新。和 scissor 一樣做遮罩，但演算法設計上更有彈性glEnable(GL_STENCIL_TEST)、glStencilFunc、glStencilOp、glStencilMask
Depth Test經典 Z-buffer 演算法（Williams, 1978）的硬體實作，用 depth buffer 讓場景前後順序正確；決定 fragment 能否覆蓋（或混合）color bufferglEnable(GL_DEPTH_TEST)、glDepthFunc、glDepthMask
Blending傳統上用於半透明（alpha transparency）：用可設定的 blending function 混合兩個顏色來源glEnable(GL_BLEND)、glBlendFunc
範例：Depth test 與 Blending 的數字
  • Depth test（GL_LESS）：某像素目前 depth buffer 存 0.6（之前畫的牆）。新 fragment 深度 0.4（比牆近）→ 0.4 < 0.6 通過，寫入顏色並把 depth 更新成 0.4。之後又來一個 0.7 的 fragment（牆後面）→ 0.7 < 0.4 不成立 → 丟掉。結果和繪製順序無關，這就是 Z-buffer 的價值。
  • 沒開 depth test：後畫的永遠蓋掉先畫的 → 牆後面的東西如果比較晚畫，會「穿透」到前面。
  • Blending（glBlendFunc(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA)）：畫面上已有藍色 (0,0,1)，新畫一個 α=0.3 的紅色玻璃 (1,0,0)：結果 = 0.3 × (1,0,0) + 0.7 × (0,0,1) = (0.3, 0, 0.7)。
開了 depth test，每幀必須 glClear(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT)，否則上一幀的深度會擋住新畫面。半透明物體通常要先畫不透明、再由遠到近畫透明。Blending 的完整說明見 講義 06。

Compute Pipeline

  • OpenGL 4.3 起提供（macOS 只到 4.1，沒有 compute shader）
  • 只有一個 programmable stage；沒有預先定義的輸入輸出，但可以非同步讀寫 buffer 和 texture → 高度客製化的平行演算法
  • 概念接近 CUDA、DirectCompute
  • 和繪圖 pipeline 建立在同樣的基礎上：可以用硬體 texture filtering 和 GLSL 內建函式
用途（越來越重要）
  • 物理模擬：水面、布料、粒子系統、音效殘響區域
  • 程序化貼圖生成
  • 影像處理：可分離的 2D 卷積（Gaussian blur…）
  • GPGPU：當作 CPU 的協同處理器、一般平行演算法
  • 講義 07 的 GPU-driven rendering（instance culling）

OpenGL 101：第一支 shader 程式

講義的程式碼區塊顏色：黃色 = Application（CPU）：建立 OpenGL context、建立與維護 OpenGL 物件、產生給 GPU 的工作；藍色 = Shader（GPU）：某個 programmable stage 的 shader，平行處理幾何或 fragment，以 #version 410 core 開頭。本頁以註解標示 C++ 或 GLSL。

講義用一系列由簡到繁的小範例。點選範例，右邊是模擬的執行結果（瀏覽器內用 JavaScript 照 shader 的邏輯逐像素算出來）：

Shader 與 Shader Program

// C++：講義的 setup_shaders()
GLuint setup_shaders()
{
    GLuint vertex_shader, fragment_shader, program;

    // create and compile the vertex shader
    vertex_shader = glCreateShader(GL_VERTEX_SHADER);
    glShaderSource(vertex_shader, 1, vs_source, NULL);
    glCompileShader(vertex_shader);

    // create and compile the fragment shader
    fragment_shader = glCreateShader(GL_FRAGMENT_SHADER);
    glShaderSource(fragment_shader, 1, fs_source, NULL);
    glCompileShader(fragment_shader);

    // create a program, attach shaders to it, and link it
    program = glCreateProgram();
    glAttachShader(program, vertex_shader);
    glAttachShader(program, fragment_shader);
    glLinkProgram(program);

    // delete the shaders as the program has them now
    glDeleteShader(vertex_shader);
    glDeleteShader(fragment_shader);
    return program;
}
函式說明
glShaderSource(shader, count, string, length)把 shader 的原始碼換成 string 陣列裡的字串（count 個）。length 為 NULL 時每個字串都視為以 '\0' 結尾
glCreateProgram()建立空的 program object，回傳非 0 的 ID
glAttachShader(program, shader)要 link 在一起的 shader 必須先 attach 到 program
glLinkProgram(program)連結成可在 GPU 上執行的程式
glUseProgram(program)把 program 裝進目前的渲染狀態
  • 編譯 shader 很吃 CPU：現代遊戲引擎常有上百上千個 shader
  • shader object 只要 input / output / global 在各 stage 間相符，就能在不同 program 間重複使用
  • 除非必要，所有 shader 和 program 都應在啟動時載入

讀檔、錯誤檢查的完整版本見 Shader Program 建立流程。

Vertex Array Object（VAO）與 glDrawArrays

  • VAO 代表 Vertex Specification stage 的輸入設定：定義 attribute layout，讓這個 stage 從 buffer 組出 VS 的輸入
  • 每種輸入設定應事先建立一個 VAO，draw 之前 bind
  • 即使完全沒有輸入，渲染也必須 bind 一個 VAO（下面 OpenGL 101 的例子就是空的 VAO）
  • glGenVertexArrays(n, arrays) 產生 n 個 VAO 名字；glBindVertexArray(array) 綁定，傳 0 解除
glDrawArrays(mode, first, count)
  • mode：GL_POINTS、GL_LINES、GL_LINE_STRIP、GL_LINE_LOOP、GL_TRIANGLES、GL_TRIANGLE_STRIP、GL_TRIANGLE_FAN、各種 _ADJACENCY、GL_PATCHES
  • 用 enabled array 中第 first 到 first + count − 1 個元素組成 primitive
  • 沒有 GL_QUADS（core profile 已移除）→ 四邊形要拆成兩個三角形

各 mode 的互動圖見 講義 05。

內建變數與 in / out

變數哪個 stage說明
out vec4 gl_PositionVertex Processing 的輸出目前頂點的位置（clip space 齊次座標）。屬於 gl_PerVertex block（另有 gl_PointSize、gl_ClipDistance[]）。只有在最後一個啟用的 vertex processing stage 才有這個意義；shader 執行中任何時候都可以寫
in int gl_VertexIDVertex shader 輸入目前頂點的整數 index，由 glDrawArrays 等指令自動產生。OpenGL 101 用它從 shader 內的常數陣列挑座標
in vec4 gl_FragCoordFragment shader 輸入目前 fragment 的視窗座標 (x, y, z, 1/w)。例：(0.5, 0.5) 是左下角第一個像素的中心
in / out storage qualifier
  • GLSL 用 in、out 修飾的全域變數讓資料進出 shader
  • 在 stage 之間，out 和 in 形成管道傳遞資料
  • Vertex attribute：VS 中的 in 變數，值由 vertex specification stage 自動填入；可用 glVertexAttrib* 設成常數
  • User-defined attribute：stage s1 宣告 out 變數 s1_v、下一個 stage s2 宣告同名的 in 變數 → s1 寫的值傳到 s2
  • FS 的輸入和其他 stage 不同：rasterizer 會在 primitive 上插值 user-defined attribute
Interface block

一個一個宣告介面變數最簡單，但要傳很多資料時，可以用像 struct 的 interface block 把變數包在一起：

// GLSL：vertex shader
out VS_OUT
{
    vec4 color;
} vs_out;          // instance 名稱可以不同

// GLSL：fragment shader
in VS_OUT          // block 名稱要相同
{
    vec4 color;
} fs_in;
